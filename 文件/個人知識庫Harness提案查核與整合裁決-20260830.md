## 0. 結論

九項提案的正式處置：

| 提案 | 裁決 | 最終落位 |
|---|---|---|
| 將 L1–L4 改名為紀錄／自動化／智慧化／協作化 | `REJECT_CANONICAL_RENAME` | 保留基礎／自動化／智慧化／自治化；協作化另作 capability dimension |
| 一般同事預設 L2 | `AMEND_PRODUCT_PRESET` | 通過 connector、consent、ACL、retention gate 後，特定來源可採 L2；不是全域架構常數 |
| `task-card/v1` YAML Schema | `AMEND_EXISTING_WORK_CARD` | 為現有 Markdown frontmatter 建 validation profile；另建 ExecutionRequest，不建立第二套 task truth |
| `session.started`、`task.finished` | `REJECT_AS_NATIVE_EVENT_NAMES` | 保存 runtime-native event，再映射成中立 semantic receipt；不得直接驅動 ACCEPTED/CLOSED |
| `memctl` | `DEFER_READ_ONLY_FACADE` | 先做 read-only feasibility；不得自帶 DB、canonical writer或promotion authority |
| Capture／Closeout／Consolidation／Promotion 四 Loop | `ADOPT_AS_DOMAIN_OPERATIONS` | 映射既有 Evidence、WorkRecord、Candidate、Governance；不建立四套 Agent／FSM／DB |
| Runtime Provider Interface | `REJECT_UNIVERSAL_PROVIDER_PLATFORM` | 只允許 thin runtime-native invocation adapter＋request/receipt mapping |
| M0–M4 | `AMEND_DELIVERY_MILESTONES` | 作 delivery sequence，不得冒充 L1–L4、Work lifecycle或Knowledge lifecycle |
| Hermes Adapter | `ADMIT_RESEARCH_SPIKE_ONLY` | Codex baseline後才可開 one-shot、sandboxed、receipt-only spike |

最高層 target：

```text
Personal Knowledge Product Authority
= Organizational Memory OS

Work / Task / Acceptance Authority
= AI Core existing Work lifecycle

Runtime execution
= Codex / Claude Code / Hermes / DSH native surface

Cross-runtime integration
= immutable ExecutionRequest
  + runtime-native invocation adapter
  + immutable ExecutionReceipt / NativeEventReceipt

Human-readable personal vault
= projection / curated personal surface
  not enterprise Knowledge authority
```

禁止重新建立：

```text
Provider Registry
Provider Database
Universal Runtime Platform
Hook Event Truth
Task Card Database
Session Truth
Agent Memory Authority
Second Canonical Writer
```

# 1. Current truth reconciliation

## 1.1 Organizational Memory OS 的既有產品真相

Personal Knowledge 現有成熟度軸：

```text
L1 基礎
L2 自動化
L3 智慧化
L4 自治化
```

Personal Knowledge 現有流程：

```text
Personal Work Sources
→ Raw Evidence
→ Object Linking
→ WorkRecord Projection
→ Knowledge Distillation
→ PERSONAL / TEAM / DEPARTMENT / COMPANY / CLIENT Candidate
→ Staging
→ Governance
```

已鎖 invariant：

```text
WorkRecord != Knowledge
Personal Memory != Company Canonical Knowledge
Personal → Team → Company
requires Proposal + Review
```

普通同事不需要：

```text
完整 AI Core
Codex
Claude Code
Hermes
獨立 Memory Runtime
```

所以「個人知識庫 Harness」若成為公司產品能力，必須讓一般同事仍能從：

```text
Outlook
Teams
Jira
文件
Web
人工上傳
```

進入 Evidence，而不是要求每個人先安裝 coding agent。

## 1.2 AI Core 的 Founder Vault 確實存在

AI Core 目前已有：

```text
.founder-vault/
├── README.md
├── memory-summary.md
├── identity/
├── context/
├── memory/
├── sop/
├── operations/
├── projects/
├── people/
└── archive/
```

因此 `identity/context/memory/sop/operations/projects/people/archive` 不是完全憑空出現。

但正式定位必須是：

```text
Founder Vault
= AI Core founder-specific curated personal surface
  / human-readable projection
  / startup digest

Founder Vault
!= Organizational Memory OS enterprise canonical store
!= Raw Evidence store
!= Work lifecycle authority
```

`memory-summary.md` 目前也明示由 legacy promotion profile管理；它是一份 founder startup digest，不是所有 source event 或 company knowledge 的 canonical truth。

> 對現有 frontmatter做 deterministic validation，而不是建立第二套 task card truth。

## 1.5 Repository-global formal hook目前是 disabled

AI Core `.codex/hooks.json` 的 current decision：


這表示 repository-global formal dispatch hook不是空白缺口，而是已做過「預設停用」裁決。


- native event存在。
- surface coverage完整。
- hook failure不會造成 authority bypass。
- reconnect／redelivery語意可處理。
- hook不會直接取得Work／Knowledge authority。

```text

不新增 session/thread truth
```

# 3. L1–L4：保留正式軸，另建協作軸

## 3.1 Canonical maturity不改名

保留：

| Level | 正式名稱 | 核心語意 |
|---|---|---|
| L1 | 基礎 | 完整可用、人工控制 |
| L2 | 自動化 | 重複工作可自動完成 |
| L3 | 智慧化 | 跨來源關聯、判斷、主動建議 |
| L4 | 自治化 | 持續監測與行動，但受Authority Gate |

提案的顯示名稱可作 UX alias：

| UX alias | 對應 |
|---|---|
| 紀錄 | 通常對應 L1 的個人Evidence能力 |
| 自動化 | 對應 L2 |
| 智慧化 | 對應 L3 |
| 協作化 | 不等於 L4；屬獨立 collaboration dimension |

## 3.2 新增 orthogonal collaboration dimension

建議：

```text
collaboration_scope
= PERSONAL
  TEAM
  DEPARTMENT
  COMPANY
  CLIENT
```

以及：

```text
collaboration_mode
= PRIVATE
  SHARED_READ
  SHARED_PROPOSE
  SHARED_REVIEW
  SHARED_PUBLISH
```

因此一顆 capability可以是：

```text
Maturity = L2
Scope = PERSONAL

或

Maturity = L1
Scope = TEAM
```

不再把「越多人協作」誤解成「越自治」。

## 3.3 一般同事預設 L2 的正確條件

不能全域硬設：

```text
every user = L2
```

建議 product preset：

```text
PERSONAL_ASSISTED_DEFAULT
```

每個 source分別判斷。

### 直接允許 L1

```text
manual upload
manual note
manual correction
manual link
```

### 通過以下 gate後可啟用 L2

```text
connector authorized
user / tenant consent recorded
source ACL可取得
retention policy已選定
deletion / permission-change path可執行
capture health可觀測
rollback可執行
```

### L3仍需 opt-in / evaluation

```text
cross-source entity linking
closeout suggestion
scope promotion suggestion
commitment extraction
risk detection
```

### L4需 capability-specific authority

不能用一個全域開關讓所有 personal knowledge能力自治。

# 4. Task Card：驗證現有格式，不另造 task truth

## 4.1 保留現有 Markdown card

Canonical card仍是：

```text
docs/task_cards/<CARD>.md
```

包含：

```text
YAML frontmatter
+ human-readable Markdown contract
```

不採：

```text
task-card/v1.yaml
→ 取代現有 Markdown card
```

## 4.2 建議 validation profile

Working name：

```text
ai-core.task-card-frontmatter.v1
```

它只驗證 frontmatter，不擁有 Work lifecycle。

### Required core fields

```yaml
id:
status:
type:
priority:
role:
execution_authorized:
implementation_authorized:
production_authorized:
```

### Conditional fields

```yaml
parent:
chain_id:
cycle:
thickness:
model:
reasoning:
model_reason:
```

### Rules

1. `id` 必須與檔案／工作身分一致。
2. `status` 必須能映射 existing `work_lifecycle_contract.v1`。
3. Authorization fields缺失不得推導為 `true`。
4. `execution_authorized=true` 不代表 implementation或production已授權。
5. Unknown extension須 namespace，不能靜默取得 authority。
6. Validator只回 PASS／FAIL＋finding，不修改卡片。

## 4.3 ExecutionRequest必須是另一份 immutable artifact

Task card回答：

> 為什麼要做、範圍是什麼、由誰審核、是否授權？

ExecutionRequest回答：

> 這一次具體要交給哪個 runtime，在什麼環境與限制下執行？

建議 working contract：

```text
ai_core.execution-request.v1
```

Minimum fields：

```yaml
request_id:
created_at:
task_card_ref:
work_id:
request_digest:

runtime:
  provider:
  adapter_profile:
  provider_version_constraint:
  mode:

workspace:
  repository:
  worktree_ref:
  base_commit:
  cwd:
  allowed_write_paths:
  forbidden_paths:

input:
  root_question:
  bounded_context_refs:
  prompt_ref:
  input_digest:

capabilities:
  allowed_tools:
  denied_tools:
  network_policy:
  external_mcp:
  subagents:
  dynamic_workflow:

limits:
  timeout_seconds:
  max_turns:
  token_budget:
  cost_budget:
  max_artifact_bytes:

authorization:
  execution_authority_ref:
  credential_route_ref:
  sandbox_policy_ref:

expected_outputs:
  artifact_kinds:
  verification_commands:
  result_schema_ref:
```

禁止放入：

```text
acceptance_status
canonical_write_authorized
knowledge_canonicality
```

因為 runtime request不能預先授予主線接受或知識寫入。

## 4.4 ExecutionReceipt

Working contract：

```text
ai_core.execution-receipt.v1
```

Minimum fields：

```yaml
receipt_id:

runtime_version:
```


# 5. Hook / Event：保存 native name，再做 semantic mapping

## 5.1 禁止發明成 native event

以下名稱不能宣稱是 Codex、Claude Code或Hermes native contract：

```text
session.started
task.finished
```

它們若保留，只能是自家 normalized semantic enum，並必須保存原始 native event。

## 5.2 `RuntimeNativeEventReceipt`

建議 minimum envelope：

```yaml
receipt_id:
runtime_provider:
runtime_version:
native_event_name:
native_event_id:
native_session_ref:
native_turn_ref:
native_item_ref:
native_task_ref:

semantic_event:
occurred_at:
received_at:

ai_core_task_ref:
execution_request_ref:

payload:
  payload_ref:
  raw_digest:
  sanitized_digest:
  retention_class:

mapping:
  mapping_profile:
  mapping_version:
  mapping_confidence:

delivery:
  delivery_id:
  redelivery_key:
```

## 5.3 Neutral semantic event enum

Phase-1只需要：

```text
RUNTIME_SESSION_OPENED
RUNTIME_TURN_STARTED
RUNTIME_ITEM_COMPLETED
RUNTIME_TOOL_COMPLETED
RUNTIME_RUN_TERMINATED
RUNTIME_TASK_SIGNAL_OBSERVED
RUNTIME_FAILURE_OBSERVED
```

不使用：

```text
TASK_ACCEPTED
TASK_CLOSED
KNOWLEDGE_VERIFIED
```

## 5.4 Native event mapping

### Codex app-server

| Native | Semantic |
|---|---|
| `thread/started` | `RUNTIME_SESSION_OPENED` |
| `turn/started` | `RUNTIME_TURN_STARTED` |
| `item/completed` | `RUNTIME_ITEM_COMPLETED` |
| `turn/completed` | `RUNTIME_RUN_TERMINATED` |
| `thread/tokenUsage/updated` | usage observation |

`turn/completed` 的 final status仍可能是：

```text
completed
interrupted
failed
```

即使是 `completed`，也只代表 turn lifecycle完成。

### Claude Code

| Native | Semantic |
|---|---|
| `SessionStart` | `RUNTIME_SESSION_OPENED` |
| `PostToolUse` | `RUNTIME_TOOL_COMPLETED` |
| `PostToolUseFailure` | `RUNTIME_FAILURE_OBSERVED` |
| `TaskCompleted` | `RUNTIME_TASK_SIGNAL_OBSERVED` |
| `Stop` | `RUNTIME_RUN_TERMINATED` |
| `StopFailure` | `RUNTIME_FAILURE_OBSERVED` |
| `SessionEnd` | `RUNTIME_RUN_TERMINATED` |

Claude Code `TaskCompleted` 表示 native task tool正在被標為完成，不得直接映射 AI Core `ACCEPTED` 或 `CLOSED`。

### Hermes

| Native | Semantic |
|---|---|
| `on_session_start` | `RUNTIME_SESSION_OPENED` |
| `post_tool_call` | `RUNTIME_TOOL_COMPLETED` |
| `post_llm_call` | turn output observation |
| `on_session_end` | run/turn end observation |
| `on_session_finalize` | session teardown observation |
| `subagent_stop` | child execution observation |
| `kanban_task_completed` | `RUNTIME_TASK_SIGNAL_OBSERVED`，Phase-1禁用 |

Hermes hook callback failure通常不應中止 agent loop；shell hook也可能因surface或版本差異未完整覆蓋。因此 Phase-1不能依賴 hook作唯一execution truth或security boundary。

## 5.5 State transition rule

只有 AI Core現有 projection／review logic可以消費 runtime receipt，並依明確規則提出 Work transition。

```text
Runtime receipt
→ Work transition proposal
→ existing Work lifecycle validation
→ reviewer / authority
→ Work state change
```

不能：

```text
task.finished event
→ CLOSED
```

# 6. `memctl`：只允許先評估 read-only façade

## 6.1 Current truth

```text

memctl database
```


但只做 read-only：

```text
path / repo identity
```

必須：

```text
permission-before-retrieval

```

## 6.3 Phase-1禁用 commands

```text
capture
write
promote
publish
delete
purge
sync
approve
canonicalize
install
enable
```

直到各自 authority contract與receipt存在。

# 7. 四個 Loop：採用語意，不建立四套子系統

## 7.1 Capture Loop

映射：

```text
Source
→ Evidence Admission
→ Raw Evidence
→ Capture Health / Gap Receipt
```

包括：

- source identity。
- chronology。
- ACL snapshot。
- payload／digest。
- quality gap。
- dedup／redelivery。

不包括：

```text
直接建立Canonical Knowledge
```

KCS也區分 capture與create：每次互動都可capture context，但不必每次都建立新article。

## 7.2 Closeout Loop

映射：

```text
Evidence / Object Links
→ WorkRecord
→ CloseoutProposal
→ Verification / Human confirmation
→ CLOSED / REOPENED
```

Closeout回答：

> 這件工作是否有結果、未結事項與交付證據？

它不回答：

> 這個結果是否已成為公司正式知識？

## 7.3 Consolidation Loop

映射：

```text
Raw Evidence / WorkRecord
→ structure
→ dedup
→ conflict / freshness
→ assertion / procedure / decision Candidate
```

可吸收KCS：

```text
Structure
Reuse
Improve
```

但不得變成：

```text
Consolidation Agent
+ Consolidation DB
+ Consolidation FSM
```

## 7.4 Promotion Loop

映射：

```text
Candidate
→ Scope Proposal
→ Permission
→ Verification
→ Acceptance
→ Canonical Single Writer
```

Personal → Team → Company不是copy，而是 authority-controlled scope promotion。

## 7.5 Loop implementation rule

四個 Loop是：

```text
domain operation groups
```

不是：

```text
四個 daemon
四個 agent
四個 queue
四個 ledger
四個 database
```

同一個 deterministic worker、model-assisted worker或human review surface可以執行其中多個 operation，只要receipt與authority分離。

# 8. Runtime adapter：允許 thin contract，拒絕 universal platform

## 8.1 可接受的最小介面

Working interface：

```text
RuntimeInvocationAdapter
```

只需要：

```text
preflight(request) -> PreflightReceipt
invoke(request) -> NativeHandle / ProcessRef
collect(handle) -> ExecutionReceipt
interrupt(handle) -> InterruptReceipt   # optional
```

它不保存 canonical state。

## 8.2 Adapter責任

- 檢查 runtime executable／version。
- 驗證 profile digest。
- 建立 one-shot invocation。
- 設定 cwd／worktree／sandbox。
- 傳入bounded input。
- 收集 stdout／stderr／native events。
- 做payload redaction與artifact reference。
- 正確處理 timeout／interrupt／process tree cleanup。
- 回傳 receipt。

## 8.3 Adapter不得負責

```text
選擇產品priority
建立Work card
改Work status
驗證交付正確
接受候選commit
merge / push / deploy
promote Knowledge
持久化provider session truth
```

## 8.4 Runtime selection

Runtime selection應由：

```text
existing task card / routing policy / owner authorization
```

決定。

不建立：

```text
runtime_providers table
provider registry service
automatic nested fallback
```

任何 fallback都必須是新ExecutionRequest或明示retry receipt，不能靜默換runtime。

# 11. Minimum tests / negative fixtures

## 11.1 Task card

- authorization field缺失不能默認true。
- unknown status不能自動塞進Work lifecycle。
- runtime event不能修改task card frontmatter。
- task card ID與ExecutionRequest task ref不一致必須fail。

## 11.2 Runtime event

- 同native event redelivery去重。
- 同native event ID不同payload產生mismatch finding。
- event沒有native ID仍保留delivery／receipt identity。
- reconnect後事件缺口標示`PARTIAL`。
- `TaskCompleted`／`turn/completed`不能映射`ACCEPTED`。
- Hook未觸發不能推導「沒有tool call」。

## 11.3 Execution receipt

- exit 0但verification未跑。
- stdout有done文字但process exit non-zero。
- timeout後child process仍活著。
- runtime偷偷fallback另一provider。
- worktree不在allowlist。
- changed path超出範圍。
- credential route缺失。
- profile digest drift。

## 11.4 Personal knowledge

- private Evidence linked到Company Object不擴權。
- mixed-scope WorkRecord不能產生unrestricted summary。
- L2 connector ACL取得失敗時退回L1／BLOCKED，不繼續capture。
- closeout proposal不能直接promotion。
- model confidence high不能取代review。
- Founder Vault summary不能直接升Company Canonical。

## 11.5 Hermes

- `chat -q`需要互動approval時不得hang。
- hook未registration時不能視為policy applied。
- native memory寫入嘗試被阻擋。
- kanban／cron／gateway capability未掛載。
- stdout／stderr與exit semantics可重建。
- shell hooks保持disabled。
- child process timeout可清理。
