## 0. Owner scope correction

本計畫**不是**把完整 AI Core 拆出來，另做一套 Personal AI Core、Personal Runtime 或獨立 Harness 平台。

正確定位：

> 個人知識庫團隊只聚焦 AI Core 的「個人記憶能力」；AI Core 的 Work、Task、Runtime、Review、Rules、Skills、Agent 與工程治理保持原樣，由 AI Core 繼續擁有。

因此：

```text
AI Core
= 完整系統，保持完整

Personal Memory Harness
= AI Core 內／旁的一個 bounded memory capability slice

Organizational Memory OS
= 提供 Evidence、Memory／Knowledge、Scope Promotion、Permission、Verification 等語意與治理 donor

Personal Memory Team
!= AI Core replacement
!= AI Core runtime team
!= provider platform team
```

本文件 supersede 先前將 Task Card、ExecutionRequest、Runtime Event、Provider Adapter、Hermes／DSH 全部拉入個人知識庫主線的過度延伸。

.memory/logs/*

.memory/archive/*

# 2. Personal Memory Harness 的真正責任

只承接以下七項。

## 2.1 Memory Source Inventory

辨識 AI Core 中哪些資料可以成為個人記憶來源：

- runtime memory log。
- accepted／closed work receipt或result reference。
- task card／handoff／decision文件 reference。
- Git commit／artifact reference。
- founder manual note／correction。
-既有 Founder Vault curated content。

它只建立來源映射，不修改 AI Core Work lifecycle。

## 2.2 Memory Evidence Admission

將記憶來源轉成既有 OMOS `RawEvidenceEnvelope` 語意：

```text
AI Core source fact／artifact
→ Raw Evidence reference
```

至少保留：

```text
source identity
source version／commit／digest
occurred／observed／received time
scope／sensitivity
payload ref／source anchor
provenance
work／verification／acceptance refs（如有）
```

不另造 Runtime Event Truth。

## 2.3 Memory Candidate Distillation

從 Evidence 萃取可長期保留的 Personal Memory Candidate。

Phase-1 memory kinds：

```text
PREFERENCE
WORKING_STYLE
PRINCIPLE
LESSON
DECISION
PROJECT_CONTEXT
PERSON_CONTEXT
PROCEDURE
LONG_LIVED_CONSTRAINT
```

下列預設不是長期記憶：

```text
current task status
one-off command output
transient open loop
temporary branch／worktree state
unverified model suggestion
```

它們可以是 Work Context，但不能因被捕捉就自動升 Personal Canonical Memory。

## 2.4 Personal Memory Governance

每筆候選至少要處理：

```text
source support
scope
sensitivity
confidence
freshness／validity
conflict
supersession
correction
retention／deletion
review requirement
```

核心 invariant：

```text
Captured != Remembered
Candidate != Personal Canonical Memory
Runtime COMPLETE != Memory Verified
Personal Memory != Company Canonical Knowledge
```

## 2.5 Personal Canonical Memory Boundary

正式路徑：

```text
Raw Evidence
→ Personal Memory Candidate
→ deterministic checks／model-assisted distillation
→ review requirement
→ acceptance
→ Personal Memory Single Writer
→ Personal Canonical Memory
```

第一版不得新增第二套企業 Knowledge DB；Personal Canonical Memory 的實體落點要先由 `PMEM-00` 確認 AI Core current truth後再決定。

## 2.6 Human-readable Projections

由 Personal Canonical Memory 編譯：

```text
.founder-vault/identity/
.founder-vault/context/
.founder-vault/memory/
.founder-vault/sop/
.founder-vault/operations/
.founder-vault/projects/
.founder-vault/people/
.founder-vault/archive/
.founder-vault/memory-summary.md
```

但 folder taxonomy 是 view，不是 source truth。

```text
memory-summary.md
= rebuildable／reviewable projection
```

不得由模型直接覆寫後即視為 canonical promotion。

## 2.7 Recall／Context Return／Correction

Personal Memory Harness 必須能將記憶以 bounded context交回 AI Core：

```text
Query／Task Intent
→ relevant Personal Memory
→ source refs／freshness／scope
→ context budget
→ AI Core consumer
```

使用者修正必須能回到：

```text
Correction Evidence
→ Candidate amendment／invalidation
→ review
→ new revision／supersession
→ projection rebuild
```

               ▼

> 這是一條 Memory loop 加回 AI Core，不是把 AI Core 切出去重建。

# 4. 與 AI Core 各能力的邊界

| AI Core能力 | Personal Memory Team角色 |
|---|---|
| Task Card／Work lifecycle | 只讀來源 reference；不改 schema、不擁有 status |
| Runtime／Codex／Claude／Hermes／DSH | 只接已存在的 bounded receipt／artifact；不建 adapter平台 |
| Review／Acceptance | 讀取結果；Personal Memory另有自己的 memory acceptance |
| Git／Worktree／Branch | 作 provenance／object link；不管理 lifecycle |
| Rules／Skills | 可成為 Procedure／Skill Candidate來源；不直接promotion |
| `.memory` | current truth audit、legacy translation、evidence source |
| `.founder-vault` | personal curated surface／projection；不取代 enterprise authority |

# 6. 記憶能力的四個 Domain Loops

不再使用「Closeout」作記憶團隊自有 loop。

## 6.1 Capture

```text
AI Core／Human／Document source
→ Evidence Admission
→ Memory Evidence
→ Capture Health／Gap
```

## 6.2 Consolidate

```text
Memory Evidence
→ classify／dedup／conflict／freshness
→ Personal Memory Candidate
```

## 6.3 Govern／Promote

```text
Candidate
→ review requirement
→ acceptance
→ Personal Canonical Memory
→ optional PERSONAL→TEAM／COMPANY Proposal
```

## 6.4 Recall／Correct

```text
Intent
→ bounded Personal Memory Context
→ AI Core use
→ user correction／new Evidence
→ amend／invalidate／supersede
```

這四個只是 domain operation groups，不建立四個 Agent、Queue、DB或FSM。

# 8. Hard Stops

禁止：

- 把 Personal Memory Harness包成「另一套 AI Core」。
- 複製 AI Core Task／Runtime／Review／Agent Team／Worktree管理。
- 將 Founder Vault folder視為完整canonical schema。
- 將 `.memory` 中檔名含 canonical 的 legacy檔直接當 current truth。
- Runtime event直接寫 Personal Canonical Memory。
- Work closeout直接等於 Memory promotion。
- Model confidence直接自動promotion。
- 個人記憶直接升 Team／Company Knowledge。
- memory-summary.md成為不可追溯的手寫最高真相。
- 為記憶團隊建立 provider registry、ExecutionRequest平台、Hermes／DSH adapter或global hook。

---

# 9. 最終一句話

> Personal Memory Harness 是「替完整 AI Core 補強記憶的能力切片」；它只整理 AI Core 已產生的 Evidence、沉澱 Personal Memory、提供可重建 Founder Vault／Context Pack，再把記憶送回 AI Core 使用。它不接管、複製或拆走完整 AI Core。
