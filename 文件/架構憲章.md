# 架構憲章

本文件定義 Organizational Memory OS 不可被 implementation convenience、donor framework、AI Core priority 或單一 runtime 改寫的核心契約。

## 一、六個 Truth Boundary

### 1. 證據 Truth

`Raw Evidence != Derived Interpretation != Knowledge`

Outlook、Teams、Slack、Jira、Git、文件、Agent 輸出、LLM 摘要、Automation 結果先是 Evidence。Evidence identity 與 provenance 必須可追溯；Knowledge 不能反寫原始 Evidence。

### 2. Knowledge Truth

`Candidate != Canonical`

Extractor、Reviewer AI、人、Agent、Importer 都只能產生 Candidate 或 Mutation Proposal；不得直接取得 Canonical write authority。

### 3. Permission Truth

`Permission-before-Retrieval`

流程固定：Identity → Role/Group → Knowledge Scope → Capability → Authorized Retrieval Space → Vector/Graph/Keyword Retrieval → Context → LLM。

模型不是權限 enforcement boundary。

### 4. Verification Truth

`Required Verification != Actual Verification`

驗證狀態至少保留：`PASS / FAIL / PARTIAL / NOT_RUN / STATIC_ONLY`。缺驗證不得視為通過；部分執行不得 aggregate 成 PASS。

### 5. Acceptance Truth

`EXECUTED != VERIFIED != ACCEPTED`

Agent 做完、Evaluation 跑完、Reviewer 批准是三件不同的事。Acceptance 狀態至少：`PENDING / ACCEPTED / REJECTED / BLOCKED`。

### 6. Mutation Truth

`Proposal != Canonical Write`

只有滿足 Permission、Verification、Acceptance 的 Proposal 才能進 Canonical Knowledge Writer。Canonical resource 採 Single Authoritative Writer。

## 二、Domain Architecture 與 Executor 分離

正式新增：

> **Knowledge Architecture != Agent Architecture**

架構優先定義產品必須存在的 domain responsibility，再決定由 deterministic code、worker、model、agent、human 或外部 runtime 執行。

以下屬產品能力時必須保留：Evidence Admission、Object/Work Context、Knowledge Governance、Conflict、Freshness、Permission、Canonical Writer、Retrieval Policy、Evaluation。

以下不得因名稱中有 Agent 就自動升格為 permanent subsystem：Resident Agent、Conflict Agent、Reviewer Agent、Validation Agent、Ingestion Agent、Evaluation Agent、Repair Agent。

若換成 deterministic code 或其他模型後產品能力仍成立，該 Agent 預設只是 executor。

## 三、Deterministic First

所有 operation 先問：不用模型能不能可靠完成？

預設路由：

```text
DETERMINISTIC_LOCAL
→ BOUNDED_CHEAP_MODEL
→ STRONG_MODEL
→ HUMAN_AUTHORITY
```

file hashing、source identity、schema/metadata validation、ACL propagation、source deletion propagation、exact duplicate、version comparison、parser execution、projection rebuild、required-field validation、lifecycle timestamps 等優先 deterministic。

semantic classification、claim extraction、ambiguous linking、conflict interpretation、summarization、candidate generation、answer generation 才使用模型。

模型強度不得取代 Verification Requirement 或 Acceptance Authority。

## 四、Projection Truth

正式新增：

```text
Chunk != Knowledge
Embedding != Knowledge
Vector DB != Canonical Database
Graph != Canonical Knowledge
```

Vector、Embedding、Chunk、Search Index、Knowledge Graph、FAQ、cache、ranking artifact 一律預設為 rebuildable projection。

Projection 可以 delete、rebuild、re-embed、換模型，而不損失 Evidence / Canonical Knowledge truth。

## 五、Object / Work Context 保留為 Domain Semantics

Object-Centric Evidence 與 Work Record Projection 不屬 Agent Runtime baggage。

一筆 Evidence 可以同時連到 Jira、Client、Order、Project、Thread、Person、Document 等多個 Object；Work Record 是可重建工作視圖，不是第二套 canonical store。

這一層用來支援普通員工在 Outlook / Teams / Jira / 文件中工作的跨來源脈絡，不要求每人持有 AI Core。

## 六、Permission / Retrieval Policy 不因 Minimal Core 降級

`Permission-before-Retrieval`、Managed Policy Floor、Authorized Retrieval Space、Context Budget、Bounded Retrieval 都是企業產品 primitive。

Minimal Core 可以簡化 executor，但不得把企業安全或 SaaS 成本治理壓縮成 prompt / agent implementation detail。

## 七、Knowledge 與 Procedure / Skill 分離

Knowledge = 知道什麼。

Procedure / Skill = 遇到問題時怎麼做。

保留：Evidence → Knowledge → Repeated Successful Pattern → Skill Candidate → Validation → Review → Published Skill。

Skill 可吸成熟格式中的 trigger、inputs、procedure、verification、failure path、references/assets；但 owner、permission、provenance、lifecycle、version、approval authority 由本產品掌握。

## 八、Multi-Agent 是 Escalation Strategy

Multi-Agent Retrieval / Evaluation 不作預設 topology，也不構成 Knowledge architecture 主骨架。

Normal Query 預設單次 authorized retrieval + answer + citation verification。

只有 High Risk、Conflict、Low Confidence、Evidence disagreement、使用者明確要求獨立驗證時才啟動 second retrieval / reviewer / counter-evidence。

Knowledge SaaS 不因此自建 Multi-Agent Runtime、Mailbox、Agent Room 或 wake daemon。

## 九、AI Core 邊界

AI Core 是 Agent Governance / Execution / Runtime / Receipt donor。

Knowledge SaaS 是 Organizational Knowledge / Evidence Ingestion / Permission / Retrieval / Review / Lifecycle / Delivery authority。

雙向整合：

```text
AI Core Execution → Receipt/Evidence → Knowledge SaaS Candidate → Review → Knowledge
Knowledge SaaS → Permission-aware bounded context → AI Core Task
```

不得形成兩套 canonical truth。

## 十、Prior-Art First

新增重要能力前必須經：Problem → Existing Seam → Prior Art Scan → Semantic/Authority Diff → Tests/Failure Cases → Algorithm/Adapter Reuse → 必要時 Dependency → 最後才 Custom Code。

正式原則：

> 借工程、保架構。

優先吸收 failure cases、regression tests、algorithm、protocol pattern、adapter、operational handling；慎重吸 dependency、storage、schema；禁止搬 canonical authority、identity、permission authority、lifecycle/FSM、task model、memory truth、knowledge truth、mutable runtime DB 當 canonical DB。

## 十一、共享研究但產品優先級獨立

AI Core 的單人資源、token、parked priority 不構成本產品 constraint。

正式原則：

> Shared Research, Independent Product Priority.

每個共享能力需獨立評估 Knowledge SaaS 的安全、產品、治理、成本、規模與商業價值。

## 十二、本輪 Rebaseline 原則

本輪只允許 `Amend / Merge / Reclassify / Simplify / Defer`，不得因 executor 瘦身直接拔除 Knowledge Governance。

完整 reconciliation 以 `文件/最小核心重基準.md` 為準。
