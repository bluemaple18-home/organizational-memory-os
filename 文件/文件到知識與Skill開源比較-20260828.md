# 文件到知識／Skill 開源比較與採用裁決

日期：2026-08-28

狀態：`RESEARCH_COMPLETE / DRAFT_INPUT / NOT_CANONICAL / DOES_NOT_CHANGE_CURRENT_FRONTIER`

本文件回答兩個問題：

1. 網路上是否有比 `virgiliojr94/book-to-skill` 更強的開源？
2. Organizational Memory OS 定義「知識庫標準文件規格」時，應直接採用哪一套？

結論先寫：

> **有比 `book-to-skill` 更強的直接競品，但沒有任何單一專案同時滿足企業 Evidence、ACL、Provenance、Conflict、Verification、Acceptance、Canonical Single Writer 與多種 Projection。**

目前最強的直接競品是：

```text
yusufkaraaslan/Skill_Seekers
```

它在多來源、衝突偵測、輸出目標、RAG／Vector 整合與工程規模上，整體已超過 `book-to-skill`。

但「標準文件規格」不應照抄 Skill Seekers，也不應照抄 book-to-skill。正確做法是組合：

```text
Skill Seekers          → Source Registry / Multi-source / Conflict / Exporter
anything-to-skill      → Gap Receipt / Visual-reading request / Source coverage honesty
book-to-skill          → Book structure / Decision layer / On-demand reference pack
DocMeld                → Bronze / Silver / Gold staged document representation
DoclingDocument        → Layout-aware normalized block schema / provenance anchors
Unstructured           → Broad element metadata / enrichment lineage / chunk-origin mapping
W3C PROV               → Entity / Activity / Agent provenance vocabulary
Web Annotation         → Source selector / target segment vocabulary
DCMI Metadata Terms    → Generic descriptive metadata vocabulary
JSON-LD                → Optional semantic interoperability layer
Agent Skills standard  → Published Skill package／progressive disclosure projection
RAGFlow / LlamaIndex   → Retrieval projection patterns only
```

---

## 1. 評估維度

本研究不是用 Stars 決定，而是分成六條能力線：

1. `SOURCE COVERAGE`：能處理哪些來源、是否有可擴充 Source Registry。
2. `DOCUMENT STRUCTURE`：是否保留 heading、page、table、image、formula、bbox、parent/child。
3. `EVIDENCE & PROVENANCE`：是否有 source identity、version、hash、location、gap、parser receipt。
4. `SEMANTIC DISTILLATION`：是否能提煉 framework、rule、procedure、conflict、decision support。
5. `PACKAGING & RETRIEVAL`：是否支援 progressive disclosure、RAG、vector、不同 Agent host。
6. `ENTERPRISE GOVERNANCE`：ACL、retention、deletion、verification、acceptance、single writer。

最後一條是所有現成專案共同缺口。

## 2. 直接競品排名

### 2.1 第一名：Skill Seekers

```text
Repository: yusufkaraaslan/Skill_Seekers
Branch: development
Pinned commit: f3972efa33fa79634b96936acf1fac321cdcf7c1
License: MIT
```

截至研究時點，Repo 約 14.8K Stars，仍在活躍更新。官方定位是把 18 種來源準備成 22 種輸出，包括 Agent Skills、LangChain、LlamaIndex、Haystack、Chroma、FAISS、Weaviate、Qdrant、Pinecone 等。

#### 它比 book-to-skill 強的地方

- 18 種來源，不只書與一般文件：docs site、GitHub、PDF、video、Word、EPUB、Jupyter、OpenAPI、PPTX、RSS、man page、Confluence、Notion、Slack/Discord、local codebase。
- 22 個輸出目標，不被 Claude／Codex Skill 綁死。
- Source Registry 與 `UnifiedSource` 類型，適合包成 adapter architecture。
- 多來源衝突偵測：missing in docs、missing in code、signature mismatch、description mismatch。
- deterministic rule-based merge 與 model-assisted merge 分開。
- 支援 semantic deduplication、hybrid retrieval、Graph RAG、quality gate、incremental update。
- 同一份 prepared asset 可輸出多種 Agent／RAG／Vector projection。

#### 不能照搬的地方

- 它的 unified merge 最後仍主要產生一個 Skill asset，不是企業 Canonical Knowledge lifecycle。
- Conflict 規則偏 documentation／code API use case，不等於通用 knowledge conflict contract。
- 沒有 tenant ACL、retention、source deletion propagation、acceptance authority、canonical single writer。
- README 的規模與品質數字是專案自述，施工前仍需用 exact test／schema／commit 做 JIT 驗證。

#### 裁決

```text
DIRECT COMPETITOR WINNER
ADAPT: Source Registry / Unified Scraping / Exporter Architecture
ABSORB: Conflict classes / Pairwise synthesis / One-prep-many-projections
DO NOT ABSORB: Skill output as canonical truth
```

### 2.2 第二名：book-to-skill

```text
Repository: virgiliojr94/book-to-skill
Pinned commit: 8a2cae63f0b1d1a3add14fc8b7688ba9cfafd9c4
License: MIT
```

#### 它仍然最強的地方

- 聚焦「書／長文件 → 可用知識包」，產品語意清楚。
- chapter-centric output、framework、mental model、anti-pattern、patterns、glossary、decision cheatsheet。
- `SKILL.md` core + on-demand chapter files 的 progressive disclosure 很實用。
- CJK／多語 chapter detection、per-run workdir、batch resilience、invisible Unicode sanitization。
- generated-skill prompt-injection scanner 與 cross-host validator。
- 對 reference／study、technical／text 的輸出深度已有明確方法。

#### 它輸給 Skill Seekers 的地方

- Source 類型與 export target 少很多。
- 沒有正式 Source Registry／multi-source conflict pipeline。
- Semantic generator 主要依一份大型 `SKILL.md` 讓 host Agent 自由產生 Markdown。
- 無 intermediate assertion schema、source-span citation、mutation proposal、verification receipt。
- Update／Fold-in 直接重寫既有 Skill。

#### 裁決

```text
BEST FOCUSED BOOK-TO-REFERENCE-PACK DONOR
ADAPT: chapter pack / decision layer / security scan
DO NOT ADOPT: raw source → published skill direct path
```

### 2.3 第三名：anything-to-skill

```text
Repository: asale-ai/anything-to-skill
Pinned commit: cf32e1b1488ea3caf09f697b65d9f249ad9a1454
License: Apache-2.0
Maturity: very new
```

#### 強項

- 文件、書、slides、spreadsheets、web、bounded crawl、llms.txt、Git repository 都能進同一 extractor。
- Repo 會記錄「沒有讀到什麼」，而不是只記錄成功輸出。
- `FileReport` 已包含：origin、method、characters、estimated tokens、page count、OCR pages、table pages、column pages、invisible code points removed。
- `RunReport` 包含 source summary、failures、visual-reading requests。
- 安裝器驗證 release SHA256。

#### 比 book-to-skill 更值得吸收的點

> **Evidence gap 本身是正式資料。**

例如：

```text
page 27 requires OCR
crawl stopped at max_pages
robots.txt withheld paths
three files failed
multi-column pages detected
```

這些都應進 `ExtractionReceipt.quality_gaps[]`，不能只印在 log。

#### 不足

- 專案仍很新，維護與 compatibility 尚未證明。
- `metadata.json` 仍不是 RawEvidence contract，缺 source version、hash、ACL、rights、retention、parser version lineage。

#### 裁決

```text
ADAPT: ExtractionReceipt / QualityGap / VisualReadRequest
REFERENCE_ONLY: whole product until maturity improves
```

### 2.4 DocMeld

```text
Repository: agentii-ai/DocMeld
Pinned commit: f2689bc0cd10617e1b7329e051eb6498253979af
README license claim: MIT
GitHub license metadata: not detected at research time
```

它不是最大的直接競品，但在中間文件結構上比 book-to-skill 完整。

#### Bronze／Silver／Gold

```text
Bronze: Source Document → Structured Elements
Silver: Elements → Page-aware JSONL
Gold: Page Document → Semantic description / keywords
```

Bronze element 已有：

```text
type
level
content
page_no
element_id
parent_id
bbox / table_data / image / formula / notes / comment
```

Silver 讓每頁保留完整 title hierarchy，可獨立成為 retrieval unit。

#### 值得吸收

- deterministic/offline extraction 與 optional model enrichment 分層。
- stage independently runnable、idempotent。
- physical page／slide 作 first-class location。
- elements 與 retrieval page representation 分開。

#### 不足

- 仍缺企業 source identity、hash/version、ACL、retention、semantic assertion、acceptance。
- Gold description/keywords 是 enrichment，不是真相。
- 授權在正式依賴前要重驗 LICENSE file，而不是只看 README badge。

#### 裁決

```text
ADAPT: staged intermediate representation
ABSORB: element hierarchy / page context
DO NOT ADOPT: Gold metadata as verified knowledge
```

### 2.5 source-to-skill、Distilly、OpenViking

這三者有局部價值，但不列主架構：

- `source-to-skill`：source-specific pack；video timestamp、paper／book／repo packaging 可作 selector donor。
- `Distilly`：interview／transcript／person knowledge distillation，可作「人腦知識萃取」參考。
- `OpenViking`：resource／memory／skill filesystem 與 L0/L1/L2 context loading；AGPL，主要作 hierarchy／progressive retrieval reference。

## 3. 底層零件冠軍

直接競品不應決定 canonical schema。真正的標準應借成熟底層零件。

### 3.1 Layout-aware document schema：DoclingDocument

Docling Core 的 `DoclingDocument` 已正式區分：

- origin
- body / furniture
- groups
- text / title / section / list / code / formula
- pictures / tables / key-value / forms
- pages
- element references
- provenance item：page number、bounding box、character span

它是目前最適合拿來做 `NormalizedDocument.blocks[]` 的主要 donor。

但 DoclingDocument 只描述「解析後文件」，不擁有 Evidence／Knowledge authority。

### 3.2 Broad element metadata：Unstructured

Unstructured 的 element metadata 適合補：

- filename／filetype／last modified／language
- coordinates／page number／parent id／category depth
- links／offsets
- table cell／HTML／extraction method
- enrichment provider／model／application order
- chunk original elements

它適合做 adapter metadata vocabulary，不應成為 canonical schema owner。

### 3.3 Complex PDF：MinerU／Docling

- MinerU 強在 reading order、formula、table、image、OCR、layout visualization；AGPL，閉源 SaaS 先 reference-only 或另談商業授權。
- Docling 強在可程式化 document model與 MIT 生態。

### 3.4 RAG ingestion／retrieval：RAGFlow

RAGFlow 強在深度文件理解、chunk template、citation、fused retrieval／reranking、異質來源 ingestion。

吸收的是：

```text
parser routing
chunk strategy
citation UX
retrieval evaluation
```

不能吸收的是：

```text
chunk = knowledge
retrieval DB = canonical truth
```

### 3.5 Published Skill package：Agent Skills standard

Agent Skills standard只規範 Skill package：

```text
SKILL.md
scripts/
references/
assets/
```

以及 frontmatter、progressive disclosure、validation。

它是 `Published Skill Projection` 的標準，不是 RawEvidence 或 Canonical Knowledge 標準。

## 5. 正式 architecture decision

不要選一套專案當整個 Knowledge OS 的 document schema。

應採：

```text
Source-specific Adapter
        ↓
OMOS RawEvidenceEnvelope
        ↓
OMOS NormalizedDocument
  └─ borrow Docling / Unstructured element semantics
        ↓
OMOS Knowledge / Procedure Candidate
  └─ borrow Skill Seekers conflict + book-to-skill decision representation
        ↓
Verification / Acceptance / Canonical Single Writer
        ↓
Projection Compiler
  ├─ Agent Skills pack
  ├─ RAG chunks
  ├─ vector/search
  ├─ graph
  └─ reviewer/impact view
```

這可同時保留：

- prior-art first
- deterministic first
- Evidence != Knowledge
- Candidate != Canonical
- Projection rebuildable
- Skill output不取得 Knowledge authority

## 6. Donor disposition

### `DIRECT_REUSE`

- Agent Skills folder／frontmatter／progressive-disclosure conventions，只用於 Published Skill Projection。

### `ADAPT`

- Skill Seekers：Source Registry、multi-source conflict、exporter interface。
- Docling：NormalizedDocument block model、page／bbox／charspan provenance。
- anything-to-skill：ExtractionReceipt quality gaps。
- book-to-skill：chapter／framework／anti-pattern／decision cheatsheet pack。
- DocMeld：Bronze／Silver stage split。
- Web Annotation：selectors。

### `ABSORB`

- W3C PROV：Entity／Activity／Agent與 derivation/revision vocabulary。
- DCMI：title、creator、language、rights、format、modified 等 generic terms。
- Unstructured：element metadata與 enrichment lineage vocabulary。
- JSON-LD：optional context／IRI extensibility，不要求 v0.1 runtime使用 RDF。

### `REFERENCE_ONLY`

- MinerU（AGPL）。
- OpenViking（AGPL）。
- RAGFlow chunk/retrieval implementation。
- LlamaIndex／Haystack node/document schema。

### `CUSTOM_DELTA`

Organizational Memory OS 必須自己擁有：

- tenant／scope identity
- RawEvidence identity／version／hash
- ACL snapshot與 permission propagation
- retention／legal hold／deletion
- source rights／redistribution policy
- semantic assertion schema
- conflict／supersession／freshness
- verification requirement／receipt
- acceptance authority
- canonical single writer
- projection rebuild／rollback
