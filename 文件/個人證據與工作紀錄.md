# 個人證據與工作紀錄

## 目的

解決一般員工不使用 Codex / Claude Code / Gemini / AI Core 時，工作如何被記錄、整理、沉澱成個人/團隊/公司知識。

正式裁決：**一般員工不需要完整 AI Core。**

        ↓

## 核心流程

```text
Activity / Evidence
  ↓
Object Linking
Jira / Client / Order / Thread / Project / Person
  ↓
Object-Centric Activity Graph
  ↓

  ↓

  ↓
Knowledge Distillation
  ↓
PERSONAL / TEAM / DEPARTMENT / COMPANY / CLIENT Candidate
  ↓
Staging
```

## Work Record 不是 Knowledge

Work Record 回答「這件工作發生了什麼」；Knowledge Candidate 回答「這件工作未來有什麼值得重用」。一個 Work Record 可以產出 0～N 個 Knowledge Candidates。

## Work Grouper

優先採低成本 deterministic / heuristic，再視信心使用 embedding / LLM：

1. explicit Jira / Order / Case ID
2. explicit link / URL / thread
3. business object / project / client
4. participants
5. time proximity
6. semantic similarity
7. 仍不確定才問人

不要求一個 Evidence 只能屬於一個 Work Record；底層採 Object-Centric Evidence，WorkRecord 是 projection。

## Closeout

Jira Closed 等有明確 signal 可自動 propose close；Email / Teams 型工作可用 explicit result、人工確認、長時間 inactive + 有 result 等 signal。AI 可提出 close proposal，但不能把不確定的工作偷偷宣告完成。

## Scope

- PERSONAL：只有本人
- TEAM：團隊
- DEPARTMENT：部門
- COMPANY：全公司
- CLIENT：特定客戶/專案

Scope promotion 不是 copy。Personal → Team → Company 需要 Proposal + Review；底層 provenance 保持同一條。

## Permission inheritance

Source ACL → Evidence ACL → Candidate Scope → Canonical Permission。

萃取不能自動放寬權限。私人 Teams chat 即使萃取出 Product Fact，也不能直接升成 COMPANY；放寬需 Authority Review。

## Prior Art

- OpenChronicle：timeline normalization、sessionization、idempotent rebuild
- DayTrail：activity→task correlation / suggestion
- OCEL 2.0：object-centric event model
- Microsoft Graph：Outlook/Teams/Calendar delta/change notification
- ActivityWatch：optional desktop activity adapter；不是 MVP 必需

## MVP 最小能力

1. Microsoft 365 / Jira Evidence ingest
2. RawEvidence Contract
3. Object linking / WorkRecord projection
4. Closeout assistance
5. Knowledge distillation
6. Scope classifier / Candidate gate

不做每人一套 Local Memory Runtime。
