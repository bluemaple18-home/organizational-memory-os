# 核心知識主幹

## 唯一主 Spine

```text
Evidence Sources
文件 / Outlook / Teams / Slack / LINE / Jira / Git
Human Upload / Agent Runtime / System Activity
        ↓
Source Adapters
        ↓
Raw Evidence
        ↓
Normalize / Parse / Validate
        ↓
Atomic Extraction / Object Linking
        ↓
Work Record Projection / Knowledge Candidate
        ↓
Knowledge Staging
        ↓
Permission / Provenance / Conflict / Scope / Freshness
        ↓
Verification Requirement / Actual Verification
        ↓
Acceptance Decision
        ↓
Canonical Knowledge Writer
        ↓
Canonical Knowledge
        ├─ Knowledge / Claim / Relation
        ├─ Procedure / Skill Relations
        └─ Lifecycle / Version / Supersession
        ↓
Rebuildable Projections
        ├─ Vector / Embedding
        ├─ Chunk / Search Index
        ├─ Knowledge Graph
        └─ Role / FAQ / Cache Projection
        ↓
Identity / Permission / Managed Policy Floor
        ↓
Authorized Retrieval Space
        ↓
Intent / Domain Classification
        ↓
Context Budget
        ↓
Bounded Retrieval
        ↓
Answer / Action + Citation / Trace
        ↓
Usage / Feedback / Evaluation Evidence
        ↺ Re-evaluation / Revision Candidate
```

## Minimal Core 責任

主 Spine 背後只認八個產品責任：

1. Source
2. Evidence
3. Object / Work Context
4. Knowledge
5. Governance
6. Projection
7. Retrieval Policy
8. Verification / Evaluation

Agent、Model、Worker、Queue、Runtime 是上述 operation 的 executor / mechanics，不構成第二套主 Spine。

## Raw Evidence 與 Derived Knowledge

Evidence identity 與 provenance 應長期可追溯；payload retention 依 tenant / source policy 決定，不要求所有原文永久複製。

至少保存：source、source identity、timestamp、producer、evidence reference、hash、extraction version、model/rule version、ACL snapshot、provenance chain。

## Evidence chronology

後補 Evidence 不得偽裝成回答當時已使用的 Evidence。Answer / Evaluation Receipt 應保存 `evidence_refs_used_at_execution` 與時間戳。新 Evidence 只能觸發新的 re-evaluation / revision。

## Staging 與 Production

Staging 是機器、審核者與治理流程工作的地方；Candidate、衝突版本、測試內容不直接暴露給正式查詢。

Outline 類平台定位為 Production / 正式知識消費面：PM、RD、一般員工、AI、Bot 查詢與引用正式知識。

Outline / Resident Agent 若存在，只能作 Content Admission / Candidate Preparation executor，不取得 Candidate → Canonical authority。

## Object-Centric Evidence

一筆 Evidence 可以同時連到 Jira、Client、Order、Project、Thread、Person 等多個 Object。Work Record 是 projection，不把 Evidence 強塞進唯一 case。

這讓 Outlook、Teams、Jira、訂單與客戶脈絡可以自然交叉，也避免要求每位員工各自維護一套 Personal AI Core。

## Projection Boundary

正式 invariant：

```text
Chunk != Knowledge
Embedding != Knowledge
Vector DB != Canonical Database
Graph != Canonical Knowledge
```

Projection 可以 delete、rebuild、re-embed、change model，而不損失 Evidence / Canonical Knowledge truth。

## Permission / Retrieval Policy

Minimal Core 不得簡化掉：

```text
Identity
→ Role / Group / Scope
→ Managed Policy Floor
→ Authorized Retrieval Space
→ Source / Authority / Freshness Routing
→ Context Budget
→ Bounded Retrieval
```

模型不是 permission enforcement boundary。

## Lifecycle

```text
CANDIDATE
→ ACTIVE
→ LOW_USAGE
→ STALE_CANDIDATE
→ REVIEW_REQUIRED
→ SUPERSEDED / ARCHIVED
```

usage / recency 只能調整 retrieval priority、觸發 freshness review、降低 context priority、建議 archive；不得單獨取得 delete authority。

## Verification / Acceptance

```text
Required Verification
→ Actual Verification
→ Acceptance
```

`EXECUTED != VERIFIED != ACCEPTED`

Missing / Partial / Not-Run verification 不得 aggregate 成 PASS。

## Executor Policy

所有 operation 優先：

```text
DETERMINISTIC_LOCAL
→ BOUNDED_CHEAP_MODEL
→ STRONG_MODEL
→ HUMAN_AUTHORITY
```

Multi-Agent Retrieval / Evaluation 只作 escalation strategy；Knowledge SaaS 不以 Agent topology 作為主架構。
