# 核心知識主幹

```text
Evidence Sources
文件 / Outlook / Teams / Slack / LINE / Jira / Git
Human Upload / Agent Runtime / System Activity
        ↓
Raw Evidence
        ↓
Normalize
        ↓
Atomic Extraction / Object Linking
        ↓
Work Record Projection / Knowledge Candidate
        ↓
Knowledge Staging
        ↓
Permission / Provenance / Conflict / Scope
        ↓
AI Review / Human Review / Verification
        ↓
Acceptance Decision
        ↓
Canonical Knowledge Writer
        ↓
Canonical Knowledge
        ├─ Knowledge Graph / Relationships
        ├─ Procedure / Skill Relations
        └─ Lifecycle / Version / Supersession
        ↓
Identity / Permission / Managed Policy Floor
        ↓

        ↓

        ↓

        ↓
Bounded Retrieval
        ↓

        ↓

        ↺ Re-evaluation / Revision Candidate
```

## Raw Evidence 與 Derived Knowledge

Evidence identity 與 provenance 應長期可追溯；payload retention 依 tenant / source policy 決定，不要求所有原文永久複製。

至少保存：source、source identity、timestamp、producer、evidence reference、hash、extraction version、model/rule version、ACL snapshot、provenance chain。

## Evidence chronology

後補 Evidence 不得偽裝成回答當時已使用的 Evidence。Answer / Evaluation Receipt 應保存 `evidence_refs_used_at_execution` 與時間戳。新 Evidence 只能觸發新的 re-evaluation / revision。

## Staging 與 Production

Staging 是機器、審核者與治理流程工作的地方；Candidate、衝突版本、測試內容不直接暴露給正式查詢。

Outline 類平台定位為 Production / 正式知識消費面：PM、RD、一般員工、AI、Bot 查詢與引用正式知識。

## Lifecycle

```text
CANDIDATE
→ ACTIVE
→ LOW_USAGE
→ STALE_CANDIDATE
→ REVIEW_REQUIRED
→ SUPERSEDED / ARCHIVED
```

usage / recency 只能調整 retrieval priority、觸發 freshness review、降低 context priority、建議 archive；不得單獨取得 delete authority。

## Object-Centric Evidence

一筆 Evidence 可以同時連到 Jira、Client、Order、Project、Thread、Person 等多個 Object。Work Record 是 projection，不把 Evidence 強塞進唯一 case。這讓 Outlook、Teams、Jira、訂單與客戶脈絡可以自然交叉。
