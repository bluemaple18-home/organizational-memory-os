# 最小核心重基準

日期：2026-08-26

本文件是 Organizational Memory OS / Company Knowledge OS 的 **Architecture Reconciliation Amendment**。

它不重新設計系統、不刪除既有產品能力，也不把 AI Core Personal Mode 的資源限制帶進公司產品。

本輪只處理一個問題：

> 哪些是真的 Knowledge Product Domain Architecture，哪些只是 Agent / Model / Worker / Runtime 的可替換執行細節？

正式原則：

> **保留 Knowledge Domain Architecture；把 Agent、Model、Worker、Runtime 降回可替換 executor。**

---

## 一、Minimal Core：八個產品責任

### 1. SOURCE

代表原始世界：文件、Jira、Outlook、Teams、Slack、Git、Database、Web、人工輸入、Personal/Agent evidence。

Source Adapter 只負責：

```text
Source
→ Evidence Contract
```

每個來源不得建立自己的 Knowledge lifecycle。

### 2. EVIDENCE

回答：「原始世界實際說了什麼？」

`Raw Evidence != Canonical Knowledge`

Evidence 至少承擔 identity、source/version、location、hash、ACL snapshot、provenance、chronology。

### 3. OBJECT / WORK CONTEXT

跨來源 Evidence 允許同時連到 Jira、Client、Project、Order、Thread、Person、Document 等多個 Object。

Work Record 是 Evidence/Object Graph 的 projection，不是第二套 source truth。

這一層屬 Organizational Evidence Semantics，不是 Agent Runtime。

### 4. KNOWLEDGE

回答：「公司目前認可、可使用的說法是什麼？」

```text
Evidence
→ Candidate / Mutation Proposal
→ Governance
→ Canonical Knowledge
```

Candidate 與 Canonical 永遠分離。

### 5. GOVERNANCE

只保留真正 Knowledge Governance：

- ACL / Permission
- Provenance
- Evidence support
- Conflict / Reclassify / Supersession
- Freshness / Lifecycle
- Review / Verification / Acceptance
- Canonical Single Writer

不得把 Agent execution lifecycle、thread/session/worktree、native subagent state 混入 Knowledge Governance。

### 6. PROJECTION

以下全部預設為可重建衍生物：

- Vector index
- Embedding
- RAG chunk
- Keyword/Search index
- Knowledge Graph
- FAQ projection
- cache / rank artifacts

正式 invariant：

```text
Chunk != Knowledge
Embedding != Knowledge
Graph != Canonical Truth
Projection must be rebuildable
```

### 7. RETRIEVAL POLICY

企業安全與成本邊界不得因「Minimal Core」被壓縮掉。

```text
Identity
→ Permission / Managed Policy
→ Authorized Retrieval Space
→ Source / Authority / Freshness Routing
→ Context Budget
→ Bounded Retrieval
```

`Permission-before-Retrieval` 與 `Context Budget` 都是產品架構 primitive，不是 Agent Runtime 細節。

### 8. VERIFICATION / EVALUATION

保留 Machine / Human / risk-based verification 與 failure routing。

```text
Required Verification
→ Actual Verification
→ Acceptance
```

`EXECUTED != VERIFIED != ACCEPTED`

驗證狀態至少保留：`PASS / FAIL / PARTIAL / NOT_RUN / STATIC_ONLY`。

### Cross-Cutting Platform Controls：不是第九顆 Minimal Core

以下能力可以是 P0/P1，也可以橫跨整個產品，但不應被誤塞成第九顆 Knowledge Domain Core：

- Telemetry / Usage / Cost
- SaaS Control Plane / Entitlement
- Config Scope / Precedence
- External Capability Admission
- Runtime / Provider Adapter
- Prior-Art-First Gate

正式分類使用 `CROSS_CUTTING_PLATFORM_CONTROL`。其中 tenant / usage / cost 等是產品 operational records；OpenTelemetry span / metric / export 是可重建或可替換的 observability projection，不是 Knowledge Truth。

---

## 二、Executor Policy：Deterministic First

架構先定義 WHAT must exist；WHO/WHAT executes it 是第二層。

所有 operation 預設依序評估：

```text
DETERMINISTIC_LOCAL
        ↓ 不足
BOUNDED_CHEAP_MODEL
        ↓ 不足
STRONG_MODEL
        ↓ 需要權威裁決
HUMAN_AUTHORITY
```

### 優先 deterministic 的工作

- file hashing
- source identity
- schema / metadata validation
- ACL propagation
- source deletion propagation
- exact duplicate detection
- version comparison
- parser execution
- deterministic chunk generation
- index / projection rebuild
- required-field validation
- lifecycle timestamps

### 適合 semantic model 的工作

- semantic classification
- claim extraction
- ambiguous entity/object linking
- conflict interpretation
- summarization
- candidate knowledge generation
- answer generation

模型輸出不得因此自動取得 canonical authority。

---

## 三、Agent / Worker / Resident Agent 的定位

Agent 名稱本身不構成 subsystem。

每個現有 `Agent / Worker / Reviewer / Resident Agent / Validation Agent / Conflict Agent / Ingestion Agent / Evaluation Agent` 都必須重新回答：

1. Product/domain responsibility 是什麼？
2. 如果換成 deterministic code，architecture 是否仍成立？
3. 如果換模型，architecture 是否仍成立？
4. 是否真的需要獨立 lifecycle / DB / registry / ledger / FSM？
5. 是否可由既有 queue / worker / runtime / provider adapter 承接？

分類原則：

- `DOMAIN_CORE`：產品責任，保留
- `EXECUTOR_ONLY`：只是可替換 executor
- `DETERMINISTIC_FIRST`：優先 deterministic 實作
- `MODEL_ASSISTED`：語意問題才用模型
- `RUNTIME_OWNED`：交既有 runtime/framework，不進 Knowledge Domain Architecture
- `PROJECTION_ONLY`：可重建衍生物
- `ENTERPRISE_GOVERNANCE`：企業安全/治理核心，不因瘦身降低
- `CROSS_CUTTING_PLATFORM_CONTROL`：重要平台控制，但不是 Knowledge Domain Core
- `DEFER`：現在不施工
- `REJECT`：目前不應引入

---

## 四、Active / Passive Ingestion 統一

保留不同入口，但統一收斂：

```text
Human Upload
API Sync
Passive Discovery
Personal Work Source
External Source
        ↓
Evidence Admission
        ↓
Raw Evidence
```

禁止不同入口各自建立 Knowledge pipeline。

---

## 五、Personal Memory 新定位

一般員工不需要完整 AI Core，也不要求每人有獨立 memory runtime。

```text
Outlook / Teams / Jira / Docs / Personal Activity
        ↓
Evidence Admission
        ↓
Object / Work Context
        ↓
Knowledge Distillation
        ↓
Personal / Team / Company / Client Candidate
        ↓
Knowledge Governance
```

Personal Memory、Codex、Claude Code、Gemini 等只可以是 richer Evidence Producer。

禁止：`Personal Memory → Canonical Company Knowledge`。

---

## 六、Resident Agent 新定位

若保留 Outline / Knowledge Resident Agent，其 architecture name 應視為：

> **Evidence Admission / Candidate Preparation Operation**

可能 executor：deterministic worker、cheap model、strong model、human。

責任可包含：

- template normalization
- schema validation
- metadata completion
- source reference verification
- evidence formatting
- required-field validation
- Candidate preparation

不得自行完成 `Candidate → Canonical Knowledge`。

---

## 七、Conflict / Review / Multi-Agent 簡化

### Conflict

Domain capability 保留：

```text
Conflict Detection
→ Conflict Set
→ Semantic Comparison（必要時）
→ Canonical Disposition
```

不預設建立 Debate Agent / Arbitration Agent / Reviewer Agent chain。

### Review

依 Risk / Conflict / Evidence Quality 分級：

- LOW：schema + provenance + deterministic checks
- MEDIUM：model-assisted verification
- HIGH：designated human / authority

### Multi-Agent

Multi-Agent Retrieval / Evaluation 是 escalation strategy，不是 default topology。

只有 High Risk、Conflict、Low Confidence、Evidence disagreement、使用者要求獨立驗證時才 fan-out。

Knowledge SaaS 不自建 Multi-Agent Runtime。

        ↓
Acceptance

Permission-before-Retrieval
        ↓

        ↓

        ↓

        ↓

Executor policy 橫跨上述 operation，但不得成為主骨架。

## 九、Backlog Amendment 原則

本輪不直接 Cancel 大量卡片，先做責任重分類：

1. `Agent card → Domain Capability card`：若 Agent 名稱其實承載真正產品能力，改名並保留能力。
2. `Runtime card → Implementation note / RUNTIME_OWNED`：不再當 architecture subsystem。
3. `Graph / Vector / Chunk / Cache → PROJECTION_ONLY`。
4. `ACL / Provenance / Conflict / Freshness / Single Writer / Permission-before-Retrieval / Context Budget / Verification → KEEP / ENTERPRISE_GOVERNANCE`。
5. `Default Multi-Agent topology → REJECT / escalation only`。
6. `Deterministic operation wrapped as Agent → SIMPLIFY / DETERMINISTIC_FIRST`。

---

## 十、Hard Stops

本輪禁止：

- 重做 Knowledge OS
- 新增第二套 Knowledge DB
- 新增第二套 workflow engine
- 為每個 Agent 建 registry / ledger / FSM
- 把 Vector / Graph / Chunk 升成 canonical truth
- Personal Memory 直接升公司知識
- Model / Spark output 直接升 canonical
- 所有 query 預設 multi-agent
- 所有 Candidate 預設 human review
- 因 AI Core Personal Mode 而降低 ACL、audit、tenant isolation、retention、source deletion、安全需求
