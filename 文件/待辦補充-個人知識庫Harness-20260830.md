## 0. Scope correction

這條工作線不是：

```text
AI Core memory carve-out
Personal AI Core
Runtime/provider/hook integration
Founder-only memory cleanup
```

正確目標：

> 為公司每位員工建立同一套 Personal Memory contract 與 lifecycle，讓不同角色、不同來源、不同 Level 的個人工作 Evidence 可沉澱成 PERSONAL 範圍記憶，並經 Proposal + Review 成為共享 Knowledge。

AI Core 的最新定位：

```text
Primary donor for proven memory / harness governance patterns
+ Developer-specific advanced source adapter
```

AI Core 不是一般員工安裝依賴；一般員工使用自己既有的 AI 平台作 executor，公司提供 Harness／Skill／rules／contract。

# 3. `EMEM-00` — Scope / Ownership / Privacy Contract

三種 personal scope mode：

```text
EMPLOYEE_PRIVATE
COMPANY_MANAGED_PERSONAL
SHARED_WORK_CONTEXT
```

核心規則仍以既有 machine-readable contract 為準。

2026-09-17 Owner 補充裁決：

```text
physical_local_storage != employee_private_ownership
```

也就是「資料存在員工電腦」不代表自動屬於 `EMPLOYEE_PRIVATE`。

### Veto boundary

- `COMPANY_MANAGED_PERSONAL`／`SHARED_WORK_CONTEXT` 的公司工作資料：員工可 correction、補 Evidence／context、標 sensitivity、要求 redaction、說明 applicability，但不能單純以「我不想傳」取代公司既有 source ACL／policy／promotion gate。
- `EMPLOYEE_PRIVATE`：未經本人 consent 不得往公司送，必須 fail closed。
- 上述不代表公司可任意讀 Personal Store；公司仍受既有 permission / review / promotion / single-writer boundary 約束。

# 12. `EMEM-09` — Weekly Personal Knowledge Harness（SSP-323）

定位：不是新 Personal AI，不是每人一套 AI Core，而是公司提供給員工既有 AI 平台使用的 Harness／Skill／規範。

```text
Existing Employee AI Platform
→ Company Personal Harness / Skill
→ Local Personal Evidence / WorkRecord / Personal Memory
→ Weekly Grill
→ Personal Memory / Promotion Candidate / NEEDS_ORG_FOLLOWUP
```

核心產品行為：

1. `runtime-neutral + platform-portable + local-first truth boundary`。
2. vendor AI memory/cache/context 不得成唯一 Personal truth。
3. Weekly Grill 每週整合本週 + 歷史資料，做 Knowledge Recovery + Discovery。
4. 動態追問高資訊價值缺口；本人可回答者當次問到有明確 disposition。
5. Batch UX，一次確認；底層逐 Candidate traceability 不變。
6. 歷史狀態至少能表達：`UNSEEN / UNCHANGED / NEW_EVIDENCE / MATERIALLY_CHANGED / CONTRADICTED` 或等價語意。
7. `UNCHANGED` 不重送。
8. Organizational Value Assessment 輸出可解釋 reasons，不假裝一個精準總分。
9. 本人無法回答但高組織價值 → `NEEDS_ORG_FOLLOWUP`；跨人 expert routing 留 Organizational Layer。
10. 公司端只收 Weekly closeout receipt，不收整週工作摘要來假裝推估完整 Knowledge Boundary。

完整卡：`.work/CARD-SSP323-WEEKLY-PERSONAL-HARNESS-20260917.md`。

```text

→ one Local Personal Store
```

2. Codex + Claude Code Host Binding：user MCP + SessionStart + safe config merge + shadow/conflict detection。
3. Cross-Host Conformance / Installer / Doctor：same-store、project narrowing、review-period continuity、install/upgrade/uninstall/rollback。
