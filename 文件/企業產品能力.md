# 企業產品能力

本文件記錄那些曾因 AI Core 個人專案限制而被低估、但在企業 SaaS 需要獨立重評的能力。

## Repository / Code Intelligence

Knowledge SaaS 若正式支援 GitHub/GitLab、RD knowledge、engineering Q&A、impact analysis、architecture understanding、coding-agent context，Repository Intelligence 應作正式產品能力。

建議位置：P1-B。不是 Knowledge Truth P0，但不能因 AI Core Lite/parked 就永遠停 Lite。

可吸：CodeNib、Google Code Wiki、PorunC/CodeWiki、FSoft-AI4Code/CodeWiki、LSP、Lanser-CLI。

## Knowledge Graph / Visualization

關係資料本身是 architecture capability：Knowledge↔Evidence↔Source↔Version↔Owner↔Conflict↔Procedure。

Reviewer Graph / Impact Navigator 可列 P1-B：讓審核者查看支持/反證、前後版本、supersession、Procedure dependencies、answer citations、impact。

Advanced exploratory graph UI 可 P2；Visualization 不是 canonical truth。

## Multi-Agent Evaluation

P1-B candidate。可做 Primary Answer / Independent Reviewer / Evidence Hunter / Counter-evidence → Compare。

只定 EvaluationStrategy，不造 Multi-Agent Runtime。

## Telemetry / Usage / Cost

P0 minimum：tenant、capability、provider/model、input/output token、retrieval/LLM latency、status/error、estimated cost。

P1 full：knowledge hit rate、citation rate、chunks、evaluation quality、cost/successful answer、SLA/capacity、customer dashboard。

正式分類：`CROSS_CUTTING_PLATFORM_CONTROL`，不是第九顆 Knowledge Domain Core。tenant、usage、cost、request status 等是產品 operational records；OTel span / metric / export 是 observability projection，不是 product truth。

## External Capability / MCP Governance

P1-A。企業 connector 會擴到 Microsoft 365、Google Drive、Slack、Jira、Confluence、GitHub/GitLab、CRM、ERP、MCP、internal API，需 source identity/trust/capability/permission/tenant policy/admission。

## Config / Managed Policy

Managed Policy Floor=P0；generic Config Scope / Precedence=P1-A。

## Skill Runtime Governance

Knowledge→Skill 在只保存 Procedure 時不必做 runtime governance；當 Level 開始支援 Install→Enable→Authorize→Execute→Observe→Deprecate 時，Skill Runtime Governance 成為該 Level 的必要依賴。

至少考慮 skill_origin、owner、trust_class、version、tenant_scope、enabled、shell/network/external_write permissions、managed_lock、runtime compatibility。

AI Core 可提供 skill format、execution runtime、receipt、verification 與 adapter donor；但 Published Skill identity、Knowledge→Skill promotion、tenant permission、version/deprecation、commercial Level 與 Canonical Knowledge relationship 仍由 Knowledge SaaS 掌握。

## Version / Compatibility Governance

P1-B。Connector、Runtime、Skill、MCP Server、Model、Embedding Model、Client Agent 都可能有版本差異。至少記 minimum_supported、maximum_tested、producer_version、consumer_version 與 `SUPPORTED / DEGRADED / UNKNOWN / UNSUPPORTED`。

## Prior-Art Freshness

不照搬 AI Core 每兩週一次。依風險分類：security-critical 高頻、core connector/runtime 中頻、research donor 低頻、reference-only 很低頻。

## Shared Blackboard

保持 Trigger-based。只有出現多 Agent/多人共同處理案件、shared hypotheses/blockers、long-running collaboration 的真實需求才做。
