# 知識庫標準文件規格 v0.1 草案

日期：2026-08-28

狀態：`DRAFT / NOT_CANONICAL / REVIEW_REQUIRED / SCHEMA_NOT_IMPLEMENTED / DOES_NOT_CHANGE_CURRENT_FRONTIER`

本規格是 Organizational Memory OS 的第一份「標準文件」草案。

它不是 Markdown 樣板，也不是 Outline 上稿格式而已。它定義：

```text
一份來源
如何成為可追溯 Evidence
如何被解析成結構化 Document
如何提出 Knowledge / Procedure Candidate
如何通過 Verification / Acceptance
如何由 Single Writer 成為 Canonical
如何再編譯成 RAG / Graph / Skill / View projection
```

正式最高原則：

```text
Source Document
!=
Raw Evidence
!=
Normalized Document
!=
Knowledge Candidate
!=
Canonical Knowledge
!=
Published Skill / RAG Chunk / Graph Projection
```

---

## 0. 規格目的

### 必須解決

1. 不同來源能進同一 Evidence contract。
2. 來源原文、解析結果、語意主張、正式知識分層。
3. 每個可用主張能追到精確 source location。
4. ACL 在 retrieval 前就能判斷。
5. 來源更新、刪除、權限改變可向下游傳播。
6. Knowledge、Procedure、Decision、Policy 不再混成 Markdown blob。
7. Chunk、Embedding、Graph、Skill 都能刪除重建。
8. Machine 與 Human 都能讀、驗證、審核、比較版本。
9. 不綁死單一 parser、vector DB、LLM、Agent Runtime 或 UI。

### 不在 v0.1 解決

- 不定義完整 Runtime Governance。
- 不定義 Agent Team／Mailbox／Workflow Engine。
- 不定義完整 Knowledge Graph ontology。
- 不要求一開始採 RDF store。
- 不要求所有內容都由人手填完整 schema。
- 不把所有 P0／P1 功能一次做成 production。

## 1. 規格分層

v0.1 正式拆成五個 schema family。

```text
OMOS-EVIDENCE
OMOS-DOCUMENT
OMOS-KNOWLEDGE
OMOS-PROCEDURE
OMOS-PROJECTION
```

### 1.1 `OMOS-EVIDENCE`

回答：

> 原始世界在某個時間、版本、權限下，實際提供了什麼？

包含 Source identity、source version、payload／payload ref、hash、ACL snapshot、timestamp、provenance、retention、deletion state、parser receipt。

### 1.2 `OMOS-DOCUMENT`

回答：

> Evidence 被 deterministic parser 解析後，形成哪些可定位、可重建的結構元素？

包含 block hierarchy、page、bbox、char span、table、image、formula、code、list、heading、source anchor、quality gap。

### 1.3 `OMOS-KNOWLEDGE`

回答：

> 從 Evidence 提出的哪些 assertion，經治理後可以成為組織正式認可的知識？

包含 fact、definition、rule、requirement、decision、metric、exception、scope、applicability、evidence links、conflict、freshness、verification、acceptance。

### 1.4 `OMOS-PROCEDURE`

回答：

> 在什麼條件下，要如何做、如何知道做對、失敗怎麼辦？

包含 trigger、precondition、input、ordered steps、permissions、tools、expected outcome、verification、failure path、rollback、side effect、human checkpoint。

### 1.5 `OMOS-PROJECTION`

回答：

> Canonical Knowledge／Procedure 要如何編譯成特定消費面的可重建產物？

包含：

- Agent Skills pack
- RAG chunks
- vector/search document
- graph projection
- FAQ／role view
- reviewer／impact view
- cache

Projection 不得反向取得 Canonical authority。

## 2. 文件種類 `document_kind`

v0.1 固定以下 top-level kinds：

```text
SOURCE_EVIDENCE
NORMALIZED_DOCUMENT
KNOWLEDGE
DECISION
POLICY
PROCEDURE
REFERENCE_PACK
EXECUTABLE_SKILL
```

### 2.1 `SOURCE_EVIDENCE`

不可變來源版本／事件的 Evidence envelope。

### 2.2 `NORMALIZED_DOCUMENT`

解析結果；可由 Source Evidence 重建。

### 2.3 `KNOWLEDGE`

可被查詢與引用的正式認知內容。

### 2.4 `DECISION`

某個時間點、scope與context下做出的選擇。

### 2.5 `POLICY`

組織強制或建議遵守的規則與例外。

### 2.6 `PROCEDURE`

可重複操作的方法、檢查與失敗處理。

### 2.7 `REFERENCE_PACK`

由 Canonical Knowledge／Procedure 編譯的只讀知識包。

```text
Projection only
```

### 2.8 `EXECUTABLE_SKILL`

會使用工具、產生外部 side effect 或修改狀態的執行型能力。

它必須另經：

```text
Install
→ Enable
→ Authorize
→ Execute
→ Observe
→ Deprecate
```

不能因為檔名是 `SKILL.md` 就被歸類為 executable。

## 3. Normative format 與 authoring format

### 3.1 Normative machine contract

正式 schema 建議採：

```text
JSON Schema 2020-12
UTF-8
RFC 3339 UTC timestamps
BCP 47 language tags
IANA media types
SHA-256 content digests
Semantic Versioning for schema versions
```

### 3.2 Human authoring view

人可使用：

```text
Markdown + YAML frontmatter
```

但 Markdown 只是 authoring／presentation view，不能是唯一 machine truth。

### 3.3 Semantic interoperability

v0.1 可預留：

```json
{
  "@context": "https://schemas.example/omos/v0.1/context.jsonld"
}
```

JSON-LD 是 optional compatibility layer，不要求第一版導入 RDF database。

### 3.4 Generic vocabularies

- DCMI Terms：title、creator、language、format、rights、modified 等描述性 metadata。
- W3C PROV：Entity、Activity、Agent、used、wasGeneratedBy、wasDerivedFrom、wasRevisionOf、wasAttributedTo。
- Web Annotation：body／target／selector概念。
- Media Fragments：audio／video time range。

這些 vocabulary 不能取代 OMOS 的 authority schema。

## 4. Logical package layout

一個標準文件 package 建議長這樣：

```text
<document-id>/
├── manifest.yaml
├── content.md
├── blocks.jsonl
├── assertions.jsonl
├── steps.jsonl
├── evidence-links.jsonl
├── assets/
├── receipts/
│   ├── extraction.json
│   ├── verification.json
│   └── acceptance.json
└── checksums.json
```

不是每種 kind 都需要全部檔案。

| File | SOURCE_EVIDENCE | NORMALIZED_DOCUMENT | KNOWLEDGE / DECISION / POLICY | PROCEDURE | PROJECTION |
|---|---:|---:|---:|---:|---:|
| `manifest.yaml` | 必須 | 必須 | 必須 | 必須 | 必須 |
| `content.md` | optional view | optional view | 必須 human view | 必須 human view | 依 projection |
| `blocks.jsonl` | optional | 必須 | optional source snapshot | optional | optional |
| `assertions.jsonl` | — | candidate only | 必須 | optional rules | optional copied view |
| `steps.jsonl` | — | candidate only | — | 必須 | optional compiled view |
| `evidence-links.jsonl` | optional | 必須 | 必須 | 必須 | 必須 source refs |
| `receipts/` | ingestion | extraction | verification/acceptance | verification/acceptance | build receipt |
| `checksums.json` | 必須 | 必須 | 必須 | 必須 | 必須 |

Production storage 可以使用 database/object store，不強迫實體資料夾。這個 layout 是 exchange／fixture／export contract。

```text

```


## 6. `OMOS-EVIDENCE`：RawEvidenceEnvelope

一筆 Raw Evidence 代表一個可識別的來源版本或事件。

```json
{
  "schema_version": "omos.evidence.v0.1",
  "evidence_id": "urn:omos:evidence:uuid",
  "tenant_id": "tenant-example",
  "source": {
    "system": "jira-cloud",
    "type": "issue",
    "native_id": "PROJ-123",
    "native_version": "updated:2026-08-28T10:01:02Z",
    "uri": "jira://site/project/PROJ-123",
    "parent_native_id": null
  },
  "chronology": {
    "event_time": "2026-08-28T10:01:02Z",
    "captured_at": "2026-08-28T10:01:10Z",
    "received_at": "2026-08-28T10:01:11Z"
  },
  "payload": {
    "media_type": "application/json",
    "payload_ref": "object://evidence/...",
    "content_sha256": "...",
    "size_bytes": 1234,
    "retention_tier": "T1"
  },
  "access": {
    "acl_snapshot_ref": "acl-snapshot://...",
    "visibility_scope_refs": ["team:product"],
    "source_permission_version": "..."
  },
  "provenance": {
    "adapter_id": "jira-cloud-adapter",
    "adapter_version": "0.1.0",
    "ingestion_mode": "WEBHOOK",
    "request_or_batch_ref": "..."
  },
  "state": {
    "deletion_state": "ACTIVE",
    "legal_hold": false
  }
}
```

### 6.1 Source identity

相同來源透過不同 ingestion route 進來，必須收斂到同一 `source native identity`：

```text
API poll
Webhook
Bulk export
Manual upload
Migration
```

Route 是 provenance，不是新的 source identity。

### 6.2 一個 Evidence package不應先合併多個來源

正式規則：

```text
One RawEvidenceEnvelope
= one source-native entity/version/event
```

多來源聚合使用：

```text
EvidenceCollection
```

不能先把 PDF A、PDF B、Jira C 串成一個全文，然後失去來源級 ACL／version／deletion。

### 7.4 Table／image／formula

- Enrichment output必須標示 provider/model/version，不得覆蓋原 block。

## 8. Source Anchor／Selector

每個 assertion／step應能指向 source segment，而不只是整份文件。

```json
{
  "anchor_id": "anchor-uuid",
  "evidence_ref": "urn:omos:evidence:uuid",
  "source_version": "...",
  "selector_type": "PDF_REGION",

    "page": 7,
    "bbox": {"x": 10.0, "y": 20.0, "width": 100.0, "height": 30.0},
    "char_start": 120,
    "char_end": 240,
    "exact_text_sha256": "..."
  }
}
```

### 8.1 Selector types

#### PDF／DOCX／PPTX

```text
page / slide
bbox
char span
block id
```

#### Web

```text

retrieved representation hash
CSS / XPath selector
TextQuote selector
TextPosition selector
```

#### Git

```text
repository
commit SHA
path
line start / end
symbol identity
blob SHA
```

#### Jira／Confluence

```text
site
project / space
issue / page id
comment / attachment / changelog id
source version
```

#### Slack／Teams／Email

```text
tenant / workspace
channel / mailbox
thread / conversation
message id
timestamp
attachment id
```

#### Audio／Video

```text
media id
time start
time end
transcript segment
frame refs
```

#### Database

```text

```

### 8.2 Anchor robustness

一個 anchor可以同時帶多種 selector：



```json
{
  "step_id": "s-001",
  "order": 1,
  "title": "確認訂單走期",
  "action": "檢查開始與結束時間是否涵蓋目前時間",
  "executor_policy": "DETERMINISTIC_FIRST",
  "tool_capability_ref": null,

  "expected_outcome": "目前時間位於有效走期內",
  "verification": {
    "method": "RULE_CHECK",

  },
  "on_failure": {
    "classification": "CONFIGURATION",
    "next_step_ref": null,
    "escalation_ref": null
  },
  "evidence_links": []

```

### 14.3 Procedure 與 Executable Skill

Procedure 是「如何做」的 canonical semantics。

Executable Skill 是 Procedure 的 runtime projection＋tool binding。

```text
Procedure Canonical
        ↓ compile
Executable Skill Candidate
        ↓ capability admission
Install / Enable / Authorize
```

不能把工具名稱硬寫進所有 Procedure；應優先使用 capability reference。

## 16. AcceptanceReceipt

Acceptance 與 Verification 分開。

```json
{
  "schema_version": "omos.acceptance-receipt.v0.1",
  "receipt_id": "ar-uuid",
  "subject_ref": "candidate-ref",
  "verification_receipt_refs": [],
  "decision": "ACCEPTED",
  "authority_ref": "team-or-person",
  "decided_at": "...",
  "conditions": [],
  "canonical_write_authorized": true
}
```

正式流程：

```text

```

禁止：


### 18.3 Reference Pack


可借 book-to-skill 的 chapter／glossary／patterns／cheatsheet，但每個內容必須能追到 canonical assertion／procedure與 source evidence。

### 18.4 Agent Skills projection

輸出遵守 Agent Skills standard：

```text

├── SKILL.md
├── references/
├── scripts/
└── assets/
```

但：

- `SKILL.md` 不是 Canonical Knowledge。
- `allowed-tools` 不得自行擴張 Managed Policy Floor。
- Reference-only Skill 不應偽裝成 executable Skill。
- Skill更新應由 projection rebuild，不直接由 Agent fold-in production檔案。

## 19. 權限／Retention／Deletion

### 19.1 Permission-before-Retrieval

```text
Identity
→ Managed Policy Floor
→ Authorized Retrieval Space
→ Context Budget
→ Retrieval
→ LLM
```

Chunk／Skill／Graph projection 必須帶可 enforcement 的 ACL filter key或 authoritative permission reference。

### 19.2 Source permission change

來源 ACL 改變後：

```text
Source ACL delta
→ RawEvidence access state
→ Candidate/Canonical impact analysis
→ Projection invalidation / rebuild
→ cache eviction
→ AnswerTrace impact audit
```

### 19.3 Source deletion

刪除不能只刪 vector：

```text
payload
normalized blocks
projection chunks
embeddings
cache
reference pack payload
```

都需要依 policy處理。

Canonical assertion若仍有其他合法 Evidence支持，可以重新計算 support set；不能無條件一起刪除，也不能無視來源撤回。

## 20. Conformance profiles

v0.1 不使用 L1/L2/L3，以免與 Commercial Capability Level 混淆。

固定以下 profile：

```text
CORE
EVIDENCE
DOCUMENT
KNOWLEDGE
PROCEDURE
PROJECTION
```

### `CORE`

通過 common manifest、identity、schema、checksum。

### `EVIDENCE`

再通過 source identity、version、chronology、ACL、payload、provenance、retention。

### `DOCUMENT`

再通過 parser receipt、block hierarchy、source anchors、quality gaps。

### `KNOWLEDGE`

再通過 assertions、evidence support、conflict/freshness、verification/acceptance。

### `PROCEDURE`

再通過 trigger、precondition、steps、verification、failure、rollback、permission。

### `PROJECTION`

再通過 source canonical refs、build receipt、ACL policy、rebuildability。

## 21. Validation gates

標準文件上線前至少經：

```text
G0 Schema Validation
G1 Identity / Hash / Version
G2 Permission / Scope / Retention
G3 Provenance / Source Anchor Coverage
G4 Semantic Support
G5 Conflict / Freshness
G6 Verification Requirement Satisfied
G7 Acceptance Authority
G8 Canonical Writer Transaction
G9 Projection Rebuild Test
```

### G3 minimum

任何 `RULE`、`REQUIREMENT`、`DECISION`、`THRESHOLD` assertion至少一個 Evidence link，除非標示：

```text
HUMAN_AUTHORITY_ORIGINATED
```

即使是 Human Authority，也仍需 decision/author identity與time receipt。

### G4 semantic support

要檢查：

- assertion 是否真由 Evidence支持
- scope／condition是否遺失
- 是否把 recommendation誤升 requirement
- 是否有 source contradiction
- 是否把 parser error當原文

Static prompt-injection scan不等於 G4 PASS。

## 28. Acceptance criteria for this specification

本草案升為 canonical architecture contract前，至少需要：

1. 以一份 PDF、一張 Jira Issue、一份 Markdown SOP跑完整 fixture。
2. 同一 Evidence經兩種 parser仍能保留相同 source identity。
3. 一個 assertion能精確回到 source segment。
4. 一個 conflict能保留兩個 assertion，不必覆寫其中一個。
5. Source ACL撤回後，retrieval projection不可再返回該內容。
6. Source deletion能觸發 projection cleanup與canonical support重算。
7. Verification FAIL不會進 Canonical。
8. Acceptance缺失不會進 Single Writer。
9. 刪除全部 projection後可由 Canonical＋Evidence receipts重建。
10. Agent Skills pack可重建，且不取得 Knowledge authority。
