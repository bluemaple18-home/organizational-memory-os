# 未決問題與已定裁決

## 已定裁決

- Evidence ≠ Knowledge
- Candidate ≠ Canonical
- Work Record ≠ Knowledge
- Knowledge ≠ Procedure / Skill
- Evaluation PASS ≠ Approval
- Agent DONE ≠ Work Complete
- Permission-before-Retrieval
- Canonical Knowledge Single Writer
- Evidence chronology 不可回寫歷史
- 一般員工不需要 AI Core；Codex/CC/Gemini 是 optional advanced Evidence Producer
- Staging 是整合/測試/審核區；Outline 類平台定位 Production 正式知識站
- Multi-Agent Evaluation 可做，但 Multi-Agent Runtime 目前不自建
- Shared Blackboard 目前 Trigger-based
- AI Core priority 不傳遞到 Knowledge SaaS
- 所有 SaaS Capability 有獨立 L1-L4，並支援 Scope Override

## 仍需 contract-level 決策

### 1. WorkRecord correlation confidence

Object linking priority 已有方向：explicit Jira/Order/Case ID > explicit link/thread > business object/project/client > participants > time > semantic similarity。仍需量化 confidence threshold 與 human-confirm boundary。

### 2. Raw Evidence payload retention

已定 immutable evidence identity + append-only provenance；仍需依 source/tenant 定義 full body、attachment、transcript、normalized excerpt 的 retention tiers 與 source deletion behavior。

### 3. Permission promotion rule

已定萃取不得自動放寬 ACL；仍需定義哪些 Authority 可以把 PERSONAL/TEAM/CLIENT Candidate promotion 到更廣 Scope，以及審核 evidence。

### 4. Work closeout

Jira Closed 可直接作 signal；Email/Teams 型工作仍需定義 explicit result、inactivity、manual close、AI close proposal 的 precedence。

### 5. Knowledge taxonomy MVP

避免 taxonomy 過重。候選方向：FACT / DECISION / FAILURE / KNOW_HOW；Procedure 走獨立 `PROCEDURE_CANDIDATE`；Industry/Product/Role 作 facet 而不是 knowledge type。需在 schema card 封版。

### 6. Canonical direct-write audit

需實際盤 ingestion、AI extraction、resident agent、human editor、conflict resolver、evaluation correction、import/migration 是否有任一路徑繞過 Promotion 直接改 Canonical。這是 P0 repo audit。

### 7. MVP acceptance metrics

架構 slice 已定，但需定量：來源覆蓋、permission regression、citation correctness、evaluation coverage、latency/token/cost budget、review turnaround。

## 研究已可收斂的三個洞

- Work correlation：OpenChronicle + DayTrail + OCEL 思路已足夠進 contract/adaptation
- Evidence retention：Event Sourcing / W3C PROV / source retention pattern 已足夠進 policy design
- Permission inheritance：OpenFGA RAG pre-filter + source ACL sync 已足夠進 Knowledge Permission Model

接下來不應再漫無目的研究這三塊，而應落 exact contract / donor file / test / adapter。
