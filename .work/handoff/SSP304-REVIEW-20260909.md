## 6. 指定加壓面

1. **`allowed_map_targets` 執行期計算**：validator 讀 `ai-task-card-record` 與
   `ai-work-record-skill` 兩份 yaml 算出允許目標。確認若上游 lifecycle events / seed keys
   被改動,本卡 fixture 會失配(fail-closed),而不是被靜默放寬。
2. **`INCOMPATIBLE_FAIL_LOUD` 未要求 `error` 或 `ok:false`**：evaluator 對 `outcome ==
   INCOMPATIBLE_FAIL_LOUD` 直接 `return nil`,沒檢查 run 是否真的帶 `error` / `ok:false`。
   一個宣稱 `INCOMPATIBLE_FAIL_LOUD` 但 `ok:true`、無 `error` 的 run 會過。是否該要求
   `INCOMPATIBLE_FAIL_LOUD` ⇒ `ok == false` 且 `present?(error)`?(傾向 P2。)
3. **版本比較是字串 exact match**：`supported_hermes_versions.include?(hermes_version)` ——
   `"1.10"` vs `"1.2"`、`"1.1.0"` vs `"1.1"` 都不相等。契約是否該定義版本正規化,還是
   exact-string 是刻意選擇(避免 semver 解析引擎)?
4. **`hermes_event_map` 的 `hermes_event` 值未檢查**：evaluator 只驗 `mapped_to`,沒驗
   `hermes_event` 是非空字串或唯一。重複 `hermes_event` 映射到不同 `mapped_to` 會過。
   是否為可接受的鬆綁?
5. **`DISABLED` 分支略過相容性 / output ref 檢查**：`outcome == DISABLED` 時直接 return
   （只擋 `adapter_output_ref` 非空）。確認這對「停用時不做任何 mapping」的語意正確,沒有
   讓畸形 disabled run 溜過。
6. **rollback evaluator 與 Hook/Harness 的三份幾乎相同**：`hermes_rollback_failure` /
   `hook_rollback_failure` / `harness_rollback_failure` 結構相同,只差 disable-switch 欄位名與
   fallback 值。是否值得抽共用 helper(現況維持 per-file self-contained,與 STD/AIWR family 一致)?
7. **duplicate JSON / YAML key**：4 個新檔經 `StrictJsonObject` / `assert_unique_yaml_mapping_keys`（lib）解析。
