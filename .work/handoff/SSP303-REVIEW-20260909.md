## 6. 指定加壓面

1. **`HARNESS_UNKNOWN_CAPABILITY` 的雙重角色**：evaluator 同一碼用在「run `execution_mode`
   （已改 `HARNESS_NOT_SEQUENTIAL`）」與「step `capability` 不在允許集」。確認 step 迴圈裡
   capability 檢查在 field/urn 檢查之後、fan-out 之前的順序,不會讓某個 mutation 打到錯誤的碼。
2. **`step` 編號未檢查連續性**：evaluator 只檢查 `failed_step` 是否 ∈ `steps.map{step}`,沒有
   要求 step 從 1 連續遞增。rollback side_effect `partial_run_record` 的 failure_state 明寫
   「step numbers not contiguous from 1」,但 evaluator 沒驗。是否該補 `HARNESS_STEP_INDEX_GAP`,
   還是留給下游 runtime?（傾向 P2/P3 backlog,想聽意見。）
3. **`step["error"]` 值型別**：`present?(step["error"])` 對非空字串 / 非空集合為 true,對 `nil`
   / `""` 為 false。若 runtime 傳 `error: false` 或 `error: 0`,`present?` 判 true（非 nil、
   不 respond_to?(:empty?)）→ 會誤判成 step 有 error。是否該收斂成「`error` 是 null 或 string」?
4. **`no_second_runtime` 只擋四個具名旗標**：一個宣稱「建了 message queue / scheduler」的 run
   若不用這四個 key,evaluator 不擋（`hard_stops` 有文字但非可驗）。這是否是可接受的邊界
   （四個旗標涵蓋 CLAUDE.md `FORBIDDEN_BY_DEFAULT` 的具名項）?
5. **fan-out 與 `execution_mode` 的一致性**:一個 run `execution_mode=SEQUENTIAL_SINGLE_AGENT`
   但某 step `fan_out:true` + 合法 `measured_gap_ref` → 目前 PASS。這是預期(單一 measured
   fan-out 例外),還是 `SEQUENTIAL_SINGLE_AGENT` 應完全禁止任何 `fan_out:true`?
6. **rollback evaluator 與 Hook 的重複**：`harness_rollback_failure` 與
   `validate_ai_work_record_hook_contract.rb` 的 `hook_rollback_failure` 結構幾乎相同
   （只差 `removable` vs `disable_switch` 與 fallback 值）。是否值得抽共用 helper,還是保持
   per-file self-contained（現況與 STD/AIWR family 一致）?
7. **duplicate JSON / YAML key**：4 個新檔經 `StrictJsonObject` / `assert_unique_yaml_mapping_keys`（lib）解析。
