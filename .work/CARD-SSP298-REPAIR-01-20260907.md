- 事實：只有 `steps` 含 `PERSONAL_MEMORY_RECORD` 時才檢查 evidence/prereq/order；`["PERSONAL_MEMORY_CANDIDATE"]` 之類可直接 allow；order check 未把第一步 `TASK_CARD_OR_WORK_RECORD` 納入；duplicate token 未擋。

### SSP298-RV-005（P1）— automated-step schema ref 與 human gate 位置無法被證明

- 事實：`input_schema_ref` / `output_schema_ref` 只用 `key?`（可為 null）；只有 boolean `human_acceptance_gate`，無 gate position 欄位，但 YAML 自己要求「gate position must be recorded」。
- 修：schema ref 改 `present?`；契約新增 `human_acceptance_gate_position`（列入 `required_per_step`）與 `allowed_gate_positions`；validator 驗 position 存在且在允許集合。補 null-ref / missing-position / bad-position 負例。

### SSP298-RV-006（P2）— TaskCard / WorkRecord forbidden authority 未完整鎖

- 事實：validator 只檢查 `forbidden_authority` 是否「包含 `memory_acceptance`」；移掉 `canonical_writer` / TaskCard `verification` gate 仍綠。
- 修：兩個 `forbidden_authority` 都做 exact-set 斷言。

### SSP298-RV-007（P2）— `TASK_CARD_DIRECT_TO_RECORD` 是 false coverage

- 事實：現有 fixture `steps: ["PERSONAL_MEMORY_RECORD"]` 靠 `before_record.empty?` 才回該 code；真正 contract 表達的 `["TASK_CARD_OR_WORK_RECORD","PERSONAL_MEMORY_RECORD"]` 會回 `PROMOTION_SKIPS_EVIDENCE`；evaluator 沒用 `origin`。
