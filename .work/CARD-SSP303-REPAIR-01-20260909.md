## 定點修法（同 branch `cc/ssp303-harness`,原 review SHA `bf08918` immutable）

1. **F-01**：`STEP_FAILED` 分支在 `failed_step ∈ step_numbers`（保留 `HARNESS_STEP_FAILURE_UNMARKED`）
   之後,新增 `HARNESS_FAILED_STEP_MISMATCH`：因 Harness 為 sequential single-agent、首個失敗即停,
   `error_steps`（`error` 非空的 step 編號集）必須剛好 `== [failed_step]`。涵蓋「failed_step 指向
   非 error step」與「多個 error step」兩種。yaml `step_failure.rule` 補述;`error_contract` 補該碼。
   新增負例 `HARNESS_NEG_FAILED_STEP_MISMATCH`（step 2 error、`failed_step: 1`）與
   `HARNESS_NEG_MULTI_ERROR_STEPS`（step 1、2 皆 error、`failed_step: 1`）。
2. **F-02**：`HARNESS_SECOND_RUNTIME` 改 fail-closed —— `run.keys.any? { |k| k.start_with?("builds_")
   && run[k] == true }`,涵蓋 `builds_scheduler` / `builds_queue` / `builds_message_bus` 等任何
   未列名 `builds_*` 旗標。yaml `no_second_runtime` 補具名 `builds_scheduler: false` /
   `builds_queue: false`（結構斷言隨 `EXPECTED_SECOND_RUNTIME_FLAGS` 6 旗標鎖 false）+ `rule`
   改寫成 fail-closed 語意。新增負例 `HARNESS_NEG_SECOND_RUNTIME_UNLISTED`（`builds_scheduler: true`）。
3. **F-03**：step 迴圈後新增 `HARNESS_STEP_INDEX_GAP`：`steps.map{step} == (1..steps.length).to_a`
   否則拒。yaml `step_failure.step_index_rule` 補述;`error_contract` 補該碼。新增負例
   `HARNESS_NEG_STEP_INDEX_GAP`（step 編號 `[1, 3]`）。
4. `required_negative_fixtures` 與 `EXPECTED_HARNESS_NEGATIVE_LABELS` 各 13 → 17。

reviewer 明確不另開的兩點（measured-gap fan-out 為 sequential 例外、`error:false/0` 的 `present?`
偏誤拒不越權）一併不改。
