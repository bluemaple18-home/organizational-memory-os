## 逐筆收法

### SSP307-F-01（P1）—— `task_complete → complete` 產生非法 transition

**驗證屬實**：`ai-task-card-record.yaml` 的 `allowed_status_transitions`
沒有 `OPEN → DONE` 這條邊（`DONE` 只能從 `IN_REVIEW` 到達）。真實 Codex 序列
`task_started, task_complete` 翻成 `start, complete` 一律產生
`HOOK_ILLEGAL_TRANSITION`。

**修法**：`task_complete → submit_review`（`OPEN → IN_REVIEW` 是合法邊）。
這同時是語意上更正確的邊界：Codex 執行完一個 turn 是「有證據發生了工作」，
不是「AIWR 治理層裁定工作已完成」——`DONE` 仍然需要一個本卡從不主動發出的、
獨立的 `complete` 事件。

### SSP307-F-02（P1）—— `turn_aborted → cancel` 把可恢復中斷升格成終態

**接受 reviewer 引用的 Codex 原始碼事實**（`Interrupt` 觸發 `TurnAborted`，
另有 `RecoverTurn` 專門用來恢復被中斷的 turn），而 `cancel → CANCELLED`
在 `ai-task-card-record.yaml` 是終態、無出邊。映射會讓一個可能還會恢復的
Codex turn 把 Work Record 永久關死。

**修法**：`turn_aborted` 移出 `lifecycle_event_map`，併入
`non_lifecycle_event_types`（8 項）。依本卡自己宣告的「不猜」原則
（`purpose.statement`），block／cancel 的判斷交給比本 Adapter 更高的層級。

### SSP307-F-03（P2）—— error_contract binding 仍是手寫清單互比

**驗證屬實**：`mapping_run_reachable`／`rollback_reachable`／
`runtime_sample_reachable` 是三個我自己寫的 `%w[...]` 常數陣列，跟 YAML
`error_contract` 的 keys 互比。新增一個 return branch、不同步這三張清單，
binding 本身完全抓不到——這正是 SSP-302 已經處理過的同類缺陷，且比
SSP-302 的原始版本更直接（連 regex 都沒有，是手寫清單）。

**修法**：沿用 `scripts/lib/loop_return_contract.rb`（SSP-302 已建立、參數化過
的 Ripper 語法樹模組，接受 `source_path` + `evaluator_name`），不新增第二套
機制。三個 evaluator 各自求 `reachable_codes`，`error_contract` 與三者聯集
機器綁定。**同時套用該模組的 `exit_shape_violations`**（bodystmt 無
rescue/else/ensure、最後一句必須是 `nil` 字面量）——只綁 reachable codes、
不綁出口形狀的話，會重新引入 SSP-302 closeout 已經修過的隱式回傳繞過缺口。
這是本卡主動延伸出 reviewer 沒明講但同一套機制天然帶的保障，於 evidence 中
明確標註為自發追加。

### SSP307-F-04（P2）—— Acceptance #1 只驗了單向涵蓋

**驗證屬實**：`codex_runtime_sample_failure` 原本只算
`observed_event_types - classified`，沒驗 `classified - observed_event_types`。
Acceptance #1 寫的是「合起來剛好等於」，是雙向相等。

**修法**：改成 `sorted_set(observed_event_types) == sorted_set(classified)`。
新增對應負例（分類清單多一個從未觀測過的事件類型），並補上
`required_negative_fixtures` 新 label。
