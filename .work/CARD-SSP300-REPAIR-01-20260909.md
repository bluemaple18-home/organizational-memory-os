## Findings 與處置

### SSP300-RV-001（P1）— Skill replay 沒跑 allowed_status_transitions
- 事實：只驗 events ∈ map keys + 首個 `start`，然後 `event_map.fetch(events.last)` 當 final；`[start, complete]`（SSP-299 明確非法 OPEN→DONE）可被接受。
- 修：`skill_transform_failure` 逐步 replay，讀 `ai-task-card-record` 的 `allowed_status_transitions`；任一步不在 table → `ILLEGAL_STATUS_TRANSITION`。`replayed_status` 用 walk 結果。補 `[start, complete]` negative。

### SSP300-RV-002（P1）— draft-card checker drift：漏 sensitive-content rule
- 事實：`draft_card_contract_valid?` 是第二份手寫版，漏 SSP-299 的 `sensitive_content_copied == true` 拒絕。
- 修：補上該規則。並標註「這是已知的第二份實作 → repo-wide Refactor 卡會抽共用 helper，SSP-299 / SSP-300 共用」。補 negative。

### SSP300-RV-003（P1）— Skill authority 沒有 human_acceptance_gate_position
- 事實：卡片 Scope 要 `human_acceptance_gate_position ∈ allowed_gate_positions`，但 YAML `authority` 沒這欄位；validator 只確認被引用集合存在。
- 修：YAML `authority.human_acceptance_gate_position: PERSONAL_ACCEPTANCE`；validator structural assert 它 ∈ `boundary.automated_step_contract.allowed_gate_positions`。mutation 探針覆蓋 invalid-position。

### SSP300-RV-004（P2）— draft_card.status 與 replayed_status 可矛盾
- 修：新增 `DRAFT_CARD_STATUS_MISMATCH`（`output.draft_card.status != output.replayed_status`）。補 negative。

### SSP300-RV-005（P2）— dry_run 沒 bool contract
- 修：`dry_run` 必須是 `true` / `false` → 否則 `DRY_RUN_NOT_BOOLEAN`。補 wrong-type negative。

### SSP300-RV-006（P2）— FAIL_LOUD 模型太鬆
- 事實：只有 `present?(output["error"]) && output["ok"] == true` 才拒；`{error: "boom"}`（無 ok）、`{error, ok: "true"}` 都放行。
- 修：`present?(output["error"]) && output["ok"] != false` → `FAIL_SILENT`（error 時必須明確 `ok: false`）。
