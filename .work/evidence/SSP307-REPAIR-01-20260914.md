## F-01 驗證：start → submit_review 是合法 transition

直接重播上游 `ai-task-card-record.yaml` 的
`lifecycle_event_to_status` + `allowed_status_transitions`：

```
first event start -> OPEN (OK)
OPEN -> IN_REVIEW via submit_review: OK
```

修法前（`a9bb40a`）的 `start → complete` 序列：`OPEN` 沒有到 `DONE` 的邊，
每一次 Codex 完成一個 turn 都會產生 `HOOK_ILLEGAL_TRANSITION`。這是本卡
merge 前就會被下游 Hook 擋下的必然失敗，reviewer 抓得完全正確。

## F-03 驗證：手寫清單互比是真缺口

修法前跑一次「新增 return branch、YAML 未同步」的 probe，在**未修正版本**
（`a9bb40a`）上實測：

```
在 codex_mapping_failure 新增一行
  return "CODEX_BRAND_NEW_UNDECLARED_CODE" if run["__probe__"] == true
（不動 YAML error_contract）
→ 完整 gate 仍然綠
```

這證明了 reviewer 的判讀：三張手寫清單只跟 YAML 互比，跟 evaluator 原始碼
完全脫鉤，新增一個沒宣告的 code 不會被抓到。

修法採用 SSP-302 已建立、參數化過的 `scripts/lib/loop_return_contract.rb`
（`source_path` + `evaluator_name` 皆為參數，不需要新增第二套機制）。三個
evaluator（`codex_mapping_failure`／`codex_rollback_failure`／
`codex_runtime_sample_failure`）各自求 `reachable_codes`，`error_contract`
與三者聯集機器綁定。

**主動延伸**：同時套用該模組的 `exit_shape_violations`（bodystmt 不得有
`rescue`／`else`／`ensure`；最後一句必須恰為 `nil` 字面量）。這是 reviewer
沒有明講的部分，但沿用同一套機制而不做選擇性擷取，是為了不重新引入
SSP-302 closeout 已經修過的隱式回傳繞過缺口——若只綁 `reachable_codes`
不綁出口形狀，evaluator 尾端換成隱式回傳一個未宣告的 code，一樣能繞過。
