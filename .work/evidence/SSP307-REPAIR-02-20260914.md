## 根因（驗證屬實）

repair-01 只做了：

```ruby
sorted_set(declared_observed.keys) == sorted_set(observed_types)   # 只比 key
runtime_sample.fetch("sampled_sessions").to_i > 0                   # 只比大於零
```

從未比對 `event_type_counts` 的**數值**，也從未把契約的 `sampled_sessions`
與 runtime sample 的 `sampled_sessions` 做機器綁定。兩份「凍結 evidence」
可以各自漂移而 gate 沒有反應——這代表其中至少一份根本不是真的凍結，
只是看起來像。

## 修法

新增兩條斷言：

```ruby
assert(declared_observed == sample_counts, ...)  # 逐 key 逐值比對
assert(declared_sampled_sessions == sample_sampled_sessions, ...)
```

放在既有 key-set 比對之後——先確認兩邊有一樣的 key 集合，再確認數值本身
逐字相符，錯誤訊息分開，方便定位是哪一層對不上。
