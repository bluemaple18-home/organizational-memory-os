## 不可翻案的六條 Truth Boundary

1. **證據不等於知識**：Outlook、Teams、Slack、Jira、文件、Agent 執行、人的操作先是 Evidence。
2. **候選不等於正式知識**：只有通過驗證與接受決策的 mutation 才能寫入 Canonical Knowledge。
3. **權限必須先於檢索**：未授權資料不能先進 Vector/Graph Search 再叫模型不要講。
4. **執行不等於驗證，驗證不等於接受**：`EXECUTED != VERIFIED != ACCEPTED`。
5. **修改提案不等於正式寫入**：Canonical Knowledge 採 Single Authoritative Writer。
6. **知識不等於流程/Skill**：Knowledge 是知道什麼；Procedure/Skill 是怎麼做。

## MVP 不是完整產品

MVP 要證明一條垂直閉環：

來源範圍分成：

- **Architecture Source Scope**：文件、Jira、Outlook、Teams 等皆接同一 Evidence Contract。
- **First Delivery Tranche**：文件 + Jira。
- **Next Source Tranche**：Outlook + Teams。

```text
文件 / Jira（第一交付批次）
Outlook / Teams（下一來源批次）
→ Evidence + Provenance
→ Object / Work Context / Candidate
→ Staging
→ Review / Conflict / Approval
→ Canonical Knowledge
→ Permission-before-Retrieval
→ Context Budget / Bounded Retrieval
→ PM/RD Answer + Citation
→ Machine/Human Evaluation
→ Failure → Correction → Re-evaluation
```

不阻塞 MVP：漂亮 Knowledge Graph、Achievement、Skill Marketplace、Shared Blackboard、Multi-Agent Runtime。

## 三個維度不能混

- **架構優先級**：P0 / P1 / P2 / Trigger-based
- **交付成熟度**：MVP / NEXT / NORTH STAR
- **商業能力等級**：L1 / L2 / L3 / L4

例如 Telemetry 可是 P0，但 MVP 只交付 L1；Repository Intelligence 可是 P1，但不一定進第一個 MVP。
